# 第4章 ゴーストのフォルダとファイル

## この章で学ぶこと

- SSP の中で、ゴーストがどこに置かれているか
- `ghost/master` と `shell/master` の役割のちがい
- ゴーストを作るときに必要なファイルと、あると便利なファイル
- 「はじめてのゴースト」（`hajimete`）のフォルダ構成
- テンプレートゴーストを土台にして作り始める方法

## ゴーストはフォルダでできている

第2章・第3章でいろいろなゴーストを遊んでみたと思います。実は、ゴーストの正体は **決まった形に並んだフォルダとファイルの集まり** です。特別なインストーラーやプログラムの登録は要りません。フォルダを正しい場所に正しい形で置けば、SSP がそれを見つけてゴーストとして扱ってくれます。

この章では、その「決まった形」を覚えます。ここがわかると、ほかの人のゴーストの中身をのぞいて勉強することもできるようになります。

### SSP の中のゴーストの置き場所

SSP は、自分のフォルダ（`ssp.exe` があるフォルダ）の下にある `ghost` フォルダからゴーストを探します。インストールしたゴーストは、ここに一つずつフォルダとして並んでいます。

```text
SSP/                      ← ssp.exe があるフォルダ
├─ ssp.exe
└─ ghost/                 ← ゴーストの置き場
    ├─ （最初から入っているゴーストのフォルダ）
    └─ hajimete/          ← これから作る「はじめてのゴースト」
```

`ghost` の下の一つひとつのフォルダを、この本では **ゴーストフォルダ** と呼びます。ゴーストフォルダの名前は半角英数字にしておくのがおすすめです（UKADOC でも英数字が推奨されています）。この本のサンプルでは `hajimete` にします。

なお、バルーンはゴーストの中ではなく、SSP 側のバルーン用の置き場にまとめて置かれ、全ゴーストで共有されます（第13章）。

> **コラム：置き場所は変えられる**
> SSP では、本体設定の「フォルダ」ページで、ゴーストを置くフォルダを追加・変更できます。最初は標準の `ghost` フォルダを使えば十分です。

## ゴーストフォルダの中身

ゴーストフォルダの中は、大きく **ghost** と **shell** の二つに分かれています。

```text
hajimete/                 ← ゴーストフォルダ
├─ ghost/
│   └─ master/            ← 心（会話・動作）の部分
└─ shell/
    └─ master/            ← 体（見た目）の部分
```

- **`ghost/master`**：ゴーストの「心」です。設定ファイル `descript.txt`、SHIORI の DLL、セリフを書いた辞書が入ります。現在の仕様では `ghost` の下は `master` しか使われません（昔の設計の名残でフォルダが一段深くなっています）。
- **`shell/master`**：ゴーストの「体」、つまり **シェル** です。表情ごとの画像や、触れる場所などの設定が入ります。`master` は最初に使われる標準のシェルで、必ず必要です。

UKADOC では、すべてのゴーストは一つの master ゴーストと一つの master シェルを持たなければならない、と決められています。逆に言えば、この二つさえそろえば、ゴーストとして動く骨組みができあがります。

### 追加シェル

`shell` の下には、`master` 以外にも好きな名前のフォルダを置けます。これを **追加シェル** と呼びます。中身の形は `master` と同じで、いくつでも置けます。追加シェルがあると、ユーザーは右クリックメニューから見た目を切り替えられます。着せ替えとは別に「まるごと別の衣装」を用意したいときに使います。

## 主なファイル

ここからは、それぞれの場所に置くファイルを見ていきます。全部を一度に覚える必要はありません。「必須」と書いたものから順にそろえていけば大丈夫です。

### ゴーストフォルダの直下

| ファイル | 必須？ | 役割 |
| --- | --- | --- |
| `install.txt` | 配布するなら必須 | インストールの設定。これがあると、nar ファイルを SSP にドラッグ＆ドロップするだけでインストールできる |
| `readme.txt` | 省略可（あると望ましい） | ゴーストの説明書。配布者や配布元を書くのが一般的。インストール時に開かれるほか、メニューからも開ける |
| `thumbnail.png` | 省略可 | メニューでゴーストを選ぶときに出る小さな画像（PNG か JPEG） |

`readme.txt` は、1 行目に `charset,UTF-8` と書いておくか、BOM 付きで保存しておけば、Shift_JIS 以外の文字コードでも読めます。SSP では `readme.txt` の代わりに Markdown 形式の `readme.md` も使えます。

`install.txt` の書き方は第5章で、配布のしかたは第15章で説明します。

### ghost/master の中

| ファイル | 必須？ | 役割 |
| --- | --- | --- |
| `descript.txt` | **必須** | ゴーストの名前や作者、使う SHIORI などを書く設定ファイル。これがないと SSP にゴーストとして認識されない |
| SHIORI の DLL | ほぼ必須 | ゴーストの頭脳。里々なら `satori.dll`、YAYA なら `yaya.dll` |
| 辞書ファイル | SHIORI による | セリフや反応を書いたテキストファイル。書き方は SHIORI ごとにまったく違う |
| SAORI の DLL | 省略可 | SHIORI の機能を広げる追加モジュール |
| `*.ico` | 省略可 | タスクトレイなどに出すアイコン |
| `*.cur` | 省略可 | ゴーストの上でのマウスカーソル |
| `thumbnail.png` | 省略可 | ゴースト選択時のサムネイル |

**SHIORI** は、SSP から「こんな出来事が起きた」という知らせを受け取り、返事のセリフを組み立てて返すプログラムです（詳しくは第7章）。ゴースト作者が毎日さわるのは、DLL そのものではなく **辞書** のほうです。

里々と YAYA では、`ghost/master` に置くファイルが次のように違います。

| | 里々 | YAYA |
| --- | --- | --- |
| SHIORI 本体 | `satori.dll` | `yaya.dll` |
| 設定ファイル | `satori_conf.txt`（初期設定） | `yaya.txt`（基礎設定ファイル。DLL と同じ名前の `.txt`） |
| 辞書 | `dic` で始まり `.txt` で終わる名前のファイル（例：`dic_talk.txt`） | 拡張子 `.dic` のファイル（`yaya.txt` で読み込むものを指定） |
| そのほか | 変数のセーブデータ（`satori_savedata.txt`）は里々が自動で作る | システム辞書（SHIORI として動くための基本部分）一式 |

それぞれの細かい中身は、第8章（里々）と第10章（YAYA）で扱います。

### shell/master の中

| ファイル | 必須？ | 役割 |
| --- | --- | --- |
| `descript.txt` | **必須** | シェルの名前や作者、バルーンの位置などの設定 |
| `surface*.png` | **必須** | **サーフェス** の画像。`surface0.png`、`surface10.png` のように番号をつける |
| `surfaces.txt` | 省略可 | サーフェスの組み立て、アニメーション、当たり判定などの設定 |
| `readme.txt` | 省略可 | シェルの説明書。ゴーストとシェルの作者が違うときは特に用意したい |
| `thumbnail.png` | 省略可 | シェル選択時のサムネイル |
| `*.pna` | 省略可 | サーフェスの半透明を表す画像（グレースケールの PNG を `.pna` に名前を変えたもの） |

**サーフェス** は、キャラクターの立ち絵一枚一枚のことです。表情ごとに番号をつけて用意し、さくらスクリプトの `\s[番号]` で切り替えます（第6章）。\0 側は `surface0`、\1 側は `surface10` が最初に表示される番号です。UKADOC では `surface0` と `surface10` は必須とされています（SSP では推奨ですが必須ではありません）。

シェルの作り方は第12章でじっくり説明します。この章では「`shell/master` に画像と `descript.txt` が入る」とだけ覚えておけば十分です。

> **注意：自動で作られるもの**
> ゴーストを動かすと、SSP や SHIORI がフォルダの中に設定やセーブデータを自動で作ることがあります（SSP の `profile` フォルダや、里々の `satori_savedata.txt` など）。これらは配布するときに含めないように気をつけます。詳しくは第15章で扱います。

## 「はじめてのゴースト」のフォルダ構成

ここまでの内容をまとめて、この本で作る「はじめてのゴースト」の完成形を見てみましょう。里々版は次のようになります。

```text
hajimete/
├─ install.txt
├─ readme.txt
├─ thumbnail.png          （省略可）
├─ ghost/
│   └─ master/
│       ├─ descript.txt
│       ├─ satori.dll
│       ├─ satori_conf.txt
│       └─ dic_*.txt       （辞書。何枚に分けるかは自由）
└─ shell/
    └─ master/
        ├─ descript.txt
        ├─ surfaces.txt
        ├─ surface0.png    （ことね）
        └─ surface10.png   （ぴーすけ）
```

YAYA 版は、`ghost/master` の中だけが次のように変わります。

```text
ghost/
└─ master/
    ├─ descript.txt
    ├─ yaya.dll
    ├─ yaya.txt
    ├─ （システム辞書一式）
    └─ *.dic               （自分で書く辞書）
```

完成形の辞書は、リポジトリの `samples/satori/hajimete/` と `samples/yaya/hajimete/` にあります。シェルの画像は同梱していないので、第12章を読みながら用意してください。

## テンプレートゴーストから始める

上のファイルを一つずつ手で用意するのは、はじめての人には少し大変です。そこでおすすめなのが、**テンプレートゴースト** を土台にする方法です。テンプレートゴーストは、「ちゃんと動く最小限のゴースト」として配布されているもので、SHIORI の DLL や基本の辞書が最初からそろっています。

公式ドキュメントで紹介されているテンプレートには、たとえば次のものがあります。

| SHIORI | テンプレート |
| --- | --- |
| 里々 | サンプルゴースト「ポストと狛犬 V2」 |
| YAYA | 「はろーYAYAわーるど（紺野ややめ）」、「SimpleYAYAテンプレート」、「紺野りりす」 |

入手先は、里々・YAYA それぞれの公式ドキュメントから案内されています（付録D 参照）。

### テンプレートを自分のゴーストにする手順

1. テンプレートゴーストを SSP にインストールします（nar ファイルを SSP にドラッグ＆ドロップ）。
2. SSP を終了してから、`ghost` フォルダの中にできたテンプレートのフォルダを丸ごとコピーし、名前を `hajimete` に変えます。
3. `hajimete/install.txt` の `directory` をフォルダ名と同じ `hajimete` に、`name` を自分のゴースト名に書き換えます。
4. `hajimete/ghost/master/descript.txt` の `name`、`sakura.name`、`kero.name`、`craftman`、`craftmanw` を自分のものに書き換えます（第5章）。
5. `homeurl` が書かれていたら消しておきます（下の注意を参照）。
6. SSP を起動し、右クリックメニューから「はじめてのゴースト」に切り替えて、起動することを確かめます。

> **注意：homeurl を消し忘れない**
> `homeurl` は **ネットワーク更新** で新しいファイルを取ってくる場所です。テンプレートの `homeurl` が残ったままだと、更新をかけたときにテンプレート作者のファイルで上書きされてしまうおそれがあります。YAYA のドキュメントでも、紺野ややめ・紺野りりすを使うときは辞書側（`yaya_string.txt`）の `homeurl` を無効にするよう注意されています。自分の `homeurl` は、配布の準備をするとき（第15章）に設定しましょう。

> **コラム：名前はかならず自分のものに**
> テンプレートの名前のまま改造すると、元のテンプレートと同じ SSP に入れたときに見分けがつかなくなります。ゴースト名・フォルダ名・作者名は、最初に自分のものに変えておくのが安全です。

## まとめ

- ゴーストは、SSP の `ghost` フォルダの下に置かれた、決まった形のフォルダです。
- ゴーストフォルダの中は `ghost/master`（心）と `shell/master`（体）に分かれ、どちらも必須です。
- `ghost/master` には `descript.txt`、SHIORI の DLL、辞書が入ります。`shell/master` には `descript.txt` とサーフェス画像が入ります。
- ゴーストフォルダの直下には、配布用の `install.txt`、説明書の `readme.txt`、サムネイルの `thumbnail.png` を置きます。
- はじめはテンプレートゴーストをコピーし、名前と `homeurl` を自分用に直してから作り始めると楽です。

## 練習問題

1. 次のファイルは、ゴーストフォルダの直下、`ghost/master`、`shell/master` のどこに置くでしょうか：`satori.dll`、`surface0.png`、`install.txt`、`surfaces.txt`

<details>
<summary>答え</summary>

- ゴーストフォルダの直下：`install.txt`
- `ghost/master`：`satori.dll`
- `shell/master`：`surface0.png`、`surfaces.txt`

</details>

2. 自分の SSP の `ghost` フォルダを開いて、最初から入っているゴーストの `ghost/master` と `shell/master` をのぞいてみましょう。`descript.txt` はありましたか。SHIORI の DLL はどんな名前でしたか。

<details>
<summary>ヒント</summary>

SSP では、開発者用機能を有効にすると「開発用パレット」の「開く/実行」から、いま表示しているゴーストやシェルのフォルダをすぐ開けます（第14章）。DLL の名前は、`descript.txt` の `shiori` の行にも書かれています。

</details>

3. テンプレートゴーストをコピーして自分のゴーストを作るとき、`homeurl` を消しておくのはなぜでしょうか。

<details>
<summary>答え</summary>

`homeurl` はネットワーク更新のファイルを取ってくる場所なので、テンプレートのものが残っていると、更新したときにテンプレート作者のファイルで自分の改造が上書きされてしまうおそれがあるからです。

</details>
