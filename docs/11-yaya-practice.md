# 第11章 YAYA 実践

## この章で学ぶこと

- イベント関数の書き方と、`reference[0]` などでイベントの情報を受け取る方法
- `if`・`case` による条件分岐と、配列・`foreach` の使い方
- つつかれ・なでられ・時報など、ユーザーの操作や時間に反応するしかけ
- 選択肢のメニューと `OnChoiceSelect`、グローバル変数の保存、トーク間隔の変更
- つまずいたときの調べ方（文字コード、エラーログ、よくある書きまちがい）

この章では、第10章で作った `dic_boot.dic` と `dic_talk.dic` に加えて、`dic_mouse.dic`・`dic_time.dic`・`dic_menu.dic` を作ります。完成形は [`samples/yaya/hajimete/`](../samples/yaya/hajimete/) にあります。

## 辞書を増やす準備

新しい辞書ファイルを作ったら、`yaya.txt` に読み込みの行を足します。ファイルを作る前に行だけ足すとエラーになるので、順番に気をつけてください。

`ghost/master/yaya.txt`

```text
// yaya.txt : basic settings for "Hajimete no Ghost" (YAYA version)
// Keep this file ASCII only.

charset, UTF-8

dicdir, yaya_base

dic, dic_boot.dic
dic, dic_talk.dic
dic, dic_mouse.dic
dic, dic_time.dic
dic, dic_menu.dic
```

YAYA では、関数はどの辞書ファイルに書いてもかまいません。ファイルを分けるのは、人間が探しやすくするためです。

## イベント関数と reference

### イベント名の関数が呼ばれる

第7章で見たように、ベースウェアは出来事が起きるたびに、イベント名をつけて SHIORI に知らせます。システム辞書は、そのイベント名と同じ名前の関数を探して呼び、返ってきた文字列をセリフとしてベースウェアに渡します。関数がなければ「何も言わない」と返してくれるので、使わないイベントは書かなくてかまいません。

### reference で情報を受け取る

イベントには、`Reference0`・`Reference1`…という追加の情報がついてきます。YAYA では、これを **`reference[0]`・`reference[1]`…** という配列の変数で読みます。システム辞書が、イベントのたびに中身を入れ替えてくれます。

何番に何が入るかはイベントごとに違うので、[UKADOC の SHIORI Event リスト](https://ukatech.shillest.net/ukadoc-spec/list/shiori-event/) や付録B で確かめてください。たとえば `OnFirstBoot` では、`reference[0]` にこれまでに消去（vanish）された回数が入ります。

### 起動・終了をととのえる

`dic_boot.dic` を仕上げます。

`ghost/master/dic_boot.dic`

```c
// はじめて起動したとき（SSP では、ここで何も返さないと OnBoot に進む）
OnFirstBoot
{
	"\1\s[10]\0\s[0]はじめまして！　わたし、ことね。\w9\1オレはぴーすけ、ことねの相棒だぴ。\w9\0\n\n\s[5]ユーザーさん、これからよろしくね。\e"
}

// ふだんの起動
OnBoot : nonoverlap
{
	"\1\s[10]\0\s[0]"
	--
	時間のあいさつ
	--
	"\w9\1"
	--
	"ぴーすけ参上だぴ。\e"
	"今日も元気にいくぴ。\e"
	"……まだねむいぴ。\e"
}

// 時刻によってあいさつを変える
時間のあいさつ
{
	if hour < 5 {
		"こんな時間にこんばんは、ユーザーさん。"
	}
	elseif hour < 11 {
		"おはよう、ユーザーさん！"
	}
	elseif hour < 18 {
		"こんにちは、ユーザーさん。"
	}
	else {
		"こんばんは、ユーザーさん。"
	}
}

// 終了するとき（最後に \- を書くこと）
OnClose
{
	"\1\s[10]\0\s[0]"
	--
	"またね、ユーザーさん。"
	"今日もおつかれさま！"
	--
	"\w9\1おやすみだぴ。\w9\-"
}
```

`OnFirstBoot` は、ゴーストを初めて起動したときに一度だけ起きるイベントです。SSP では、ここで何も返さないと続けて `OnBoot` が起きます。

## 条件分岐

### if / elseif / else

`時間のあいさつ` で使ったのが `if` です。条件が正しい（**真**）ときだけ、続く `{ }` の中を実行します。`elseif` は「そうでなくて、もし…なら」、`else` は「どれにも当てはまらなければ」です。

```c
if 条件 {
	…
}
elseif 別の条件 {
	…
}
else {
	…
}
```

条件には `==`（等しい）、`!=`（等しくない）、`<`・`>`・`<=`・`>=`、`&&`（かつ）、`||`（または）が使えます。`elseif` は 1 語です。`else if` と離して書くとエラーになります。

`if` の中にさらに `if` を書くときは、外側の `if` の `{ }` を省略できません。この本では、いつも `{ }` を書くようにしています。

### case / when

1 つの値によって分かれるときは、`case` が読みやすくなります。

```c
case 値 {
	when 0 {
		…
	}
	when 1-4 {
		…
	}
	when 7, 12 {
		…
	}
	others {
		…
	}
}
```

`when 1-4` は「1 から 4 まで」、`when 7, 12` は「7 か 12」です。どれにも当てはまらないときは `others` が実行されます。`when` に書けるのは、`0` や `"Head"` のような **そのままの値だけ** です。変数や計算式は書けません。

## マウスに反応する

### つつかれ（ダブルクリック）

`OnMouseDoubleClick` は、キャラクターがダブルクリックされたときのイベントです。

| reference | 中身 |
| --- | --- |
| `reference[3]` | \0 側なら 0、\1 側なら 1 |
| `reference[4]` | クリックされた場所の当たり判定の名前（判定の外なら空） |

**当たり判定** は、シェルの画像の上に設定した「頭」「顔」などの領域で、名前はシェルの `surfaces.txt` で決まります（第12章）。この本のシェルでは、ことねに `Head`（頭）・`Face`（顔）・`Bust`（胸）、ぴーすけに `Head` を付けています。名前は大文字・小文字まで一致させて比べます。

ここでは、ことねの `Head` と `Face` で反応を変え、それ以外の場所ならメニューを出します。当たり判定の名前によって分かれるので、条件分岐の節で学んだ `case` を使います。

`ghost/master/dic_mouse.dic`（前半）

```c
// ダブルクリックされた
OnMouseDoubleClick
{
	if TOINT(reference[3]) == 0 {
		case reference[4] {
			when "Head" {
				ことね_頭つつき
			}
			when "Face" {
				ことね_ほっぺつつき
			}
			others {
				メニュー
			}
		}
	}
	else {
		ぴーすけ_つつき
	}
}

ことね_頭つつき : nonoverlap
{
	"\0\s[2]ひゃっ！　頭はつつかないでー。\e"
	"\0\s[2]わっ、びっくりした。\w9\1\s[10]今のはユーザーさんの仕業だぴ。\e"
	"\0\s[1]もう、髪がくしゃくしゃになっちゃう。\e"
}

ことね_ほっぺつつき : nonoverlap
{
	"\0\s[1]ほっぺ、つつかないでよー。\e"
	"\0\s[2]むにっ。\w9\n\n……今の、わたしの声じゃないからね。\e"
}

ぴーすけ_つつき : nonoverlap
{
	"\1\s[11]つつくなぴ！\e"
	"\1\s[11]ぴぴっ、くすぐったいぴ。\w9\0\s[5]ぴーすけ、喜んでるね。\e"
	"\1\s[10]オレはおもちゃじゃないぴ。\e"
}
```

`TOINT` は値を整数にする組み込み関数です。数として比べたい値は、こうして型をそろえておくと安心です。ことねの頭と顔以外（`Bust` や、判定のない場所）をダブルクリックしたときは、`others` に進んで後で作る `メニュー` を呼びます。

### なでられ（マウスの移動）

伺かの「なでる」は、当たり判定の上でマウスを動かすことです。マウスが動くたびに `OnMouseMove` が起きるので、頭の上で動いた回数を数え、一定の回数に達したら反応させます。

`ghost/master/dic_mouse.dic`（後半）

```c
// ゴーストを読み込んだとき（しゃべらない初期化処理だけを書く）
OnGhostLoad
{
	なで回数 = 0
	// なで回数は保存しなくてよいので、終了時に消してもらう
	SHIORI3FW.RegisterTempVar("なで回数")
}

// マウスが動いた（なでられ判定）
OnMouseMove
{
	if TOINT(reference[3]) == 0 && reference[4] == "Head" {
		なで回数 += 1
		if なで回数 >= 30 {
			なで回数 = 0
			なで合計 += 1
			ことね_なでられ
		}
	}
	else {
		なで回数 = 0
	}
}

ことね_なでられ
{
	if なで合計 == 1 {
		"\0\s[1]わ、なでてくれるの？\w9\n\nえへへ、ありがとう。\e"
	}
	else {
		"\0\s[1]えへへ、くすぐったいよ。\w9\n\n（なでてもらったの、これで%(なで合計)回目）\e"
		"\0\s[5]ユーザーさんの手、あったかいね。\e"
		"\0\s[1]もう、子ども扱いしないでよー。\w9\1\s[10]まんざらでもない顔だぴ。\e"
	}
}
```

ポイントは 3 つです。

- 頭の外でマウスが動いたら `なで回数` を 0 に戻すので、頭の上で続けて動かしたときだけ反応します。`30` は好みで調整してください。
- `OnMouseMove` は頻繁に起きるイベントです。何も話さないときは空のまま終わるように、セリフは条件を満たしたときだけ返しています。
- `ことね_なでられ` の `else` の中には候補が 3 つあり、そこからランダムに 1 つが選ばれます。`if` の中でも候補のしくみはそのまま使えます。

`OnGhostLoad` は、システム辞書がゴーストの読み込み時に呼んでくれる関数です。ここでセリフを返しても表示されないので、変数の準備だけを書きます。`SHIORI3FW.RegisterTempVar` は、システム辞書が用意している「終了時に消すグローバル変数」を登録する関数です。

## 時報

SSP では、毎正時（○時 0 分ごろ）に `OnHourTimeSignal` が起きます。時刻はシステム辞書の `hour` で読めるので、`case` で分けます。

`ghost/master/dic_time.dic`

```c
OnHourTimeSignal
{
	"\1\s[10]\0\s[0]"
	--
	時報のことば
	--
	"\e"
}

時報のことば
{
	case hour {
		when 0 {
			"0時だよ。日付が変わったね。"
		}
		when 1-4 {
			"%(hour)時……。\w9\nユーザーさん、そろそろ寝たほうがいいよ。"
		}
		when 7 {
			"7時！　朝ごはん、ちゃんと食べた？"
		}
		when 12 {
			"お昼の12時。ごはんの時間だよ。"
		}
		when 15 {
			"3時だよ。\w9\1おやつの時間だぴ！"
		}
		others {
			"%(hour)時になったよ。"
		}
	}
}
```

`OnHourTimeSignal` は SSP のイベントです。ゴーストが話せない状態のときは、話せるようになるまで待ってから届くので、少し遅れることがあります。試すときは、`\![raise,OnHourTimeSignal]` をスクリプト入力から送ると、今の時刻の時報が聞けます。

## 配列と foreach

**配列** は、複数の値を順番に並べて 1 つの変数に入れたものです。`( )` の中にカンマで並べて作り、`[番号]` で取り出します。番号は 0 から数えます。

ランダムトークを 3 つ増やして、配列を使ってみましょう。`dic_talk.dic` の `OnAiTalk` の最後に候補を足し、関数を 2 つ追加します。

`ghost/master/dic_talk.dic`（追加部分）

```c
OnAiTalk : nonoverlap
{
	（中略：第10章の 10 個）

	// 配列と添字
	"\1\s[10]\0\s[0]もうすっかり%(季節のことば)だね。\w9\1季節が変わるのは早いぴ。\e"

	// foreach で配列を回す
	持ち物トーク

	// 夜ふかしの時間だけ増える候補
	if hour >= 22 || hour < 5 {
		"\1\s[10]\0\s[0]ふあぁ……そろそろ眠くなってきちゃった。\w9\1夜ふかしは体に悪いぴ。\e"
	}
}

// 配列から月に合った季節を取り出す
季節のことば
{
	_季節 = ("冬", "冬", "春", "春", "春", "夏", "夏", "夏", "秋", "秋", "秋", "冬")
	_季節[month - 1]
}

// foreach で配列の要素を1つずつ取り出す
持ち物トーク
{
	_持ち物 = ("ひまわりの種", "小さな羽根", "青いビー玉")
	_一覧 = ""
	foreach _持ち物 ; _もの {
		_一覧 += "・" + _もの + "\n"
	}
	"\0\s[0]\1\s[10]オレの宝物を見せてやるぴ。\n\n" + _一覧 + "\w9\nぜんぶで%(ARRAYSIZE(_持ち物))個だぴ。\w9\0\s[2]……そのビー玉、わたしのじゃない？\e"
}
```

- `季節のことば` では、`month`（1〜12）から 1 を引いた番号で、12 個並べた季節を取り出しています。
- `foreach 配列 ; 変数 { … }` は、配列の要素を先頭から 1 つずつ変数に入れて、`{ }` の中をくり返します。`ARRAYSIZE` は配列の要素の数を返す組み込み関数です。
- `OnAiTalk` の中の `if` は、条件が真のときだけ候補が 1 つ増えるしかけです。夜遅い時間だけ、眠そうなトークが混ざります。

## 選択肢とメニュー

### 選択肢を出す

さくらスクリプトの `\q[表示する文字,ID]` で選択肢を出せます。ユーザーが選ぶと `OnChoiceSelect` が起き、`reference[0]` に選ばれた選択肢の ID が入ります。

ID は `menu_talk` のように、半角英小文字とアンダーバーで決めておくと扱いやすくなります。

`ghost/master/dic_menu.dic`（前半）

```c
// ことねをダブルクリックしたときに出すメニュー
メニュー
{
	"\1\s[10]\0\s[0]なにかご用？\n\n/
	\q[おしゃべりして,menu_talk]\n/
	\q[トークの間隔を変える,menu_interval]\n/
	\q[なでてもらった回数,menu_count]\n/
	\q[なんでもない,menu_cancel]\e"
}

// トーク間隔を選ぶメニュー
間隔メニュー
{
	"\0\s[0]"
	--
	if aitalkinterval > 0 {
		"いまは%(aitalkinterval)秒ごとにお話ししてるよ。"
	}
	else {
		"いまはお話しをお休みしてるよ。"
	}
	--
	"\n\n/
	\q[1分ごと,interval_60]\n/
	\q[3分ごと,interval_180]\n/
	\q[10分ごと,interval_600]\n/
	\q[しばらく静かにして,interval_0]\e"
}
```

長い文字列は、第10章で学んだ行末の `/` で折り返しています。

### 選ばれた ID で分ける

`ghost/master/dic_menu.dic`（後半）

```c
// 選択肢が選ばれた（reference[0] に選択肢の ID が入る）
OnChoiceSelect
{
	case reference[0] {
		when "menu_talk" {
			OnAiTalk
		}
		when "menu_interval" {
			間隔メニュー
		}
		when "menu_count" {
			"\0\s[0]ユーザーさんになでてもらったのは、ぜんぶで%(なで合計)回だよ。\e"
		}
		when "interval_60" {
			aitalkinterval = 60
			"\0\s[5]じゃあ、1分ごとにお話しするね。\e"
		}
		when "interval_180" {
			aitalkinterval = 180
			"\0\s[5]3分ごとにお話しするね。\e"
		}
		when "interval_600" {
			aitalkinterval = 600
			"\0\s[0]10分ごとにしておくね。\e"
		}
		when "interval_0" {
			aitalkinterval = 0
			"\0\s[0]……しばらく静かにしてるね。\w9\1\s[10]用があったら呼ぶぴ。\e"
		}
		others {
			"\0\s[0]はーい。\e"
		}
	}
}
```

「おしゃべりして」では、ランダムトークの関数 `OnAiTalk` をそのまま呼んでいます。イベント用の関数も、ふつうの関数と同じように呼び出せます。「なんでもない」（`menu_cancel`）は、どの `when` にも当てはまらないので `others` に進みます。

## 変数の保存

`_` で始まらないグローバル変数は、ゴーストの終了時に `ghost/master/yaya_variable.cfg` へ自動で保存され、次の起動時に元に戻ります。なでられの `なで合計` は、何度ゴーストを起動し直しても数え続けます。

一度ゴーストを終了して `yaya_variable.cfg` をテキストエディタで開くと、次のような行が見つかるはずです。

```text
なで合計,3,",",
```

保存まわりで知っておきたいことをまとめます。

- 保存したくない変数は、ローカル変数にするか、前の節の `SHIORI3FW.RegisterTempVar` で登録します。
- グローバル変数を完全に消したいときは、`ERASEVAR("変数名")` を使います。
- 開発中に変数をまっさらに戻したいときは、ゴーストを終了してから `yaya_variable.cfg` を削除します。
- 配布するときは `yaya_variable.cfg` を入れないようにします（第15章）。

## トーク間隔

ランダムトークの間隔は、グローバル変数 `aitalkinterval`（秒）で決まります。メニューでこの値を書き換えたので、次のランダムトークから新しい間隔になります。`0` にするとランダムトークは止まります。

`aitalkinterval` もグローバル変数なので、ユーザーが選んだ間隔は保存され、次に起動したときも同じ間隔のままです。

> **注意**
> 初めて起動したときに入る値（180 秒）は、システム辞書の `yaya_base/config.dic` で決まっています。ただし、一度保存された `aitalkinterval` があると、そちらが優先されます。`config.dic` を書き換えても間隔が変わらないときは、`yaya_variable.cfg` を消してから試してください。

## よくあるつまずき

### 文字コード

- `yaya.txt` に `charset, UTF-8` がないと、辞書は Shift_JIS として読まれます。UTF-8 で保存した辞書を Shift_JIS として読むと（その逆も）、大量の謎のエラーになります。
- 辞書ファイルの保存形式と `charset` の指定を必ずそろえます。サンプルはすべて UTF-8（BOM なし）で保存しています。
- `yaya.txt` 自体は半角英数字だけで書きます。

### エラーの調べ方

1. **実行ログを出す。** `yaya.txt` に `log, yaya.log` を足して起動し直すと、`ghost/master/yaya.log` に YAYA の実行ログが書き出されます。読み込み時のエラーもここで確かめられます。ただし、毎秒届く `OnSecondChange` やマウスのイベントまで記録されてログが大きくなるので、必要なら次のように記録から外します。

   ```text
   log, yaya.log
   iolog.filter.keyword, OnSecondChange
   iolog.filter.keyword, OnMouse
   ```

   ログを取りっぱなしにすると動作が重くなるので、調べ終わったら行の頭に `//` をつけて止めましょう。

   SSP の開発用パレットには「SHIORI内部ログ機能有効」というスイッチもあります。これはオン・オフを SHIORI に知らせるだけのもので、ログを取るかどうかは SHIORI 側（YAYA ではシステム辞書）の作りしだいです（第14章）。

2. **玉（たま）を使う。** YAYA 用のデバッグツール「玉」を起動してからゴーストを起動すると、エラーが赤い文字で表示されます。行の左端が辞書のファイル名、カッコの中が行番号です。使い方は [玉を使った辞書エラーチェック](https://yaya-shiori.github.io/yaya-docs/tips/tama-error-check/) を見てください。

3. **SSP の通信ログを見る。** 開発用パレットの「SHIORI呼出ログ有効」をオンにすると、SSP と SHIORI のやりとりが `ghost/master/ssp_SHIORI_log.txt` に書き出されます（第14章）。どのイベントが届き、何が返ったかを確かめられます。

### よくある書きまちがい

| 症状・エラー | よくある原因 |
| --- | --- |
| まったく動かない | `"` や `{ }` の閉じ忘れ。同じ名前の関数を 2 つ書いた |
| `elseif` のところでエラー | `else if` と離して書いた。`if` なしで `elseif` から始めた |
| `case` のところでエラー | `case 値` のあとの `{` を忘れた。`when` に変数や式を書いた |
| セリフに謎の `0` や `1` が混ざる | 代入の `=` を比較の `==` と書いた（`a == 1` は代入ではなく、比べた結果が候補になる） |
| たまに何も話さない | 空の文字列が候補に混ざっている |
| 1 行に書いた候補でエラー | `"A" "B"` のように 1 行に 2 つ並べた |
| 変数がいつも空 | 変数名の大文字・小文字や全角・半角がちがう。ローカル変数を `{ }` の外で使った |

記号（`(`・`)`・`+`・`=` など）は、すべて半角で書きます。全角の記号は使えません。

## まとめ

- イベントと同じ名前の関数を書くと、システム辞書が呼んでくれる。イベントの情報は `reference[0]` などで読む。
- `if`／`elseif`／`else` と `case`／`when`／`others` で分岐する。`when` にはそのままの値しか書けない。
- `OnMouseDoubleClick` でつつかれ、`OnMouseMove` の回数を数えてなでられ、SSP の `OnHourTimeSignal` で時報を作れる。
- 配列は `( )` で作って `[番号]` で取り出し、`foreach` で順に回す。
- `\q[文字,ID]` で選択肢を出し、`OnChoiceSelect` の `reference[0]` で分ける。グローバル変数は自動で保存され、`aitalkinterval` でトーク間隔を変えられる。
- 困ったら、文字コードの指定、実行ログ、玉、SSP の通信ログの順に確かめる。

## 練習問題

1. ぴーすけの頭（当たり判定 `Head`）をなでたときにも反応するように、`OnMouseMove` を書き換えてください。ことねとぴーすけで、なでた回数は別々に数えます。

<details>
<summary>ヒント</summary>

`reference[3]` が 1 のときの分岐を足し、`ぴーすけなで回数` のような別の変数で数えます。どちらでもない場所では、両方の回数を 0 に戻しましょう。

</details>

2. 時報で、18 時から 20 時までのあいだは「晩ごはん何かな？」と言うようにしてください。

<details>
<summary>答え</summary>

`時報のことば` の `case` に、`others` より前に次を足します。

```c
		when 18-20 {
			"%(hour)時。晩ごはん何かな？"
		}
```

</details>

3. メニューに「ユーザーさんの好きな色」を聞く項目を足し、選んだ色をグローバル変数に覚えさせ、ランダムトークでその色の話をさせてください。

<details>
<summary>ヒント</summary>

`メニュー` に `\q[好きな色を教える,menu_color]` を足し、`OnChoiceSelect` の `when "menu_color"` で `\q[赤,color_red]` などの選択肢を出します。`when "color_red"` で `好きな色 = "赤"` のように代入し、`OnAiTalk` に `if 好きな色 != "" { … %(好きな色) … }` という候補を足します。

</details>

4. ゴーストが何も話さなくなりました。調べる順番を 3 つ挙げてください。

<details>
<summary>答え</summary>

例：(1) 辞書の保存形式と `yaya.txt` の `charset` が一致しているか確かめる。(2) `log, yaya.log` を有効にするか、玉を使って、エラーの出たファイル名と行番号を確かめる。(3) 直前に書き換えた部分の `"` や `{ }` の閉じ忘れ、同名の関数がないかを見直す。

</details>
