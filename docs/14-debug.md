# 第14章 テストとデバッグ

## この章で学ぶこと

- SSP の開発者用機能を有効にする方法と、開発中のおすすめ設定
- 開発用パレットの使い方
- ゴースト・シェル・SHIORI を再読み込みする方法
- さくらスクリプトを直接実行して試す方法
- SHIORI のエラーの見つけ方と、配布前のチェックリスト

ゴーストは、書いて、動かして、直すことのくり返しで育っていきます。この章では、その「動かして確かめる」を速く確実にするための SSP の機能を紹介します。

## 開発者用機能を有効にする

SSP の開発用の機能は、最初は隠れています。まず表に出しましょう。

1. ことねを右クリックし、「設定」→「本体設定」を開く。
2. 「一般」のページで「開発者用機能を有効にする」をオンにする。
3. 最初にオンにしたときは確認のダイアログが出ることがあるので、先へ進む。

これで、本体設定に「開発/その他」のページが現れ、右クリックメニューの「機能」に開発用の項目が増えます。キーボードの近道も使えるようになります。

| 機能 | ショートカット |
| --- | --- |
| 開発用パレット | Ctrl + Shift + D |
| スクリプトログ | Ctrl + L |
| スクリプト入力 | Ctrl + S |
| サーフィステスト | Ctrl + T |

### 開発中のおすすめ設定

SSP ヘルプでは、開発中は「開発/その他」のページを次のようにしておくことが勧められています。

- **フォルダをドロップした際に更新ファイルやNARを作成**：オン。第15章の配布ファイル作りに使います。
- **サーフィスが存在しない時に非表示とする**：オン。ふつうは存在しない番号を `\s` で指定すると基本の絵が出るので、間違いに気づきにくいのです。オンにすると、キャラクターが消えるのですぐわかります。
- **Vanish（アンインストール）実行を抑制**：オン。開発中のゴーストをうっかり消さないためです。
- **[XXX]レベル以上のエラー発生を通知**：NOTICE。小さな記述ミスも知らせてもらえます。
- **例外ハンドラを使う**：オフ。重大なエラーをもみ消さず、きちんと止まるようにします。

## 開発用パレット

**開発用パレット** は、開発に役立つスイッチと道具を1か所に集めた画面です。右クリックメニューの「機能」→「開発用パレット」か、Ctrl + Shift + D で開きます。パレットの設定はゴーストごとに覚えられます。

### よく使うチェックボックス

| 項目 | 使いどころ |
| --- | --- |
| 当たり判定を表示 | シェルの当たり判定を名前つきの枠で表示（第12章） |
| バルーンテストモード | バルーンに文字数の目安などを表示（第13章） |
| SHIORI呼出ログ有効 | SSP と SHIORI のやりとりを記録（後述） |
| 自動切替無効 | 開発中のゴーストが勝手に別のゴーストに切り替わるのを防ぐ |
| 自動更新無効 | ネットワーク更新で開発中のファイルが上書きされる事故を防ぐ |
| 更新チェックのみ | ネットワーク更新をしてもファイルを上書きせず、更新イベントの動作だけを試せる（第15章） |
| `\-`タグで終了しない | 終了の `\-` を含むトークを、ゴーストを終わらせずに試せる |

### よく使うボタン

- **スクリプト入力**：さくらスクリプトを直接打ち込んで実行します（次の節）。
- **サーフィステスト**：サーフェスを1枚ずつ表示し、アニメーションや当たり判定の一覧を確かめます。
- **エラーログを表示**：SSP が見つけたエラーの一覧です。
- **現在時刻の仮想的変更**：パソコンの時計を変えずに、SSP が思う日時だけを変えます。「朝のあいさつ」や「誕生日のトーク」のテストに便利です。
- **SERIKO Inspector**：シェルの定義を、サーフェスごとに `element`・`collision`・`animation` の木構造で見られます。
- **リロード**：メニューから選んだものを読み込み直します。
- **開く/実行**：使用中のゴースト・シェル・バルーンのフォルダを開いたり、SHIORI のログを開いたりします。

## 再読み込み：書き換えたら読み直す

辞書やシェルを書き換えても、SSP は読み込み済みの内容で動き続けます。書き換えたら、必ず読み直しましょう。方法はいくつかあります。

- **開発用パレットの「リロード」**：出てくるメニューから読み直したいものを選びます。
- **右クリックメニューの「ゴースト切り替え」で自分自身を選ぶ**：いま動いているゴーストと同じものを選ぶと、読み直しになります。
- **さくらスクリプトで指示する（SSP）**：次の節のスクリプト入力から実行できます。

| スクリプト | 読み直すもの |
| --- | --- |
| `\![reload,shiori]` | SHIORI（辞書をすべて読み直す） |
| `\![reload,shell]` | シェル |
| `\![reload,descript]` | すべての `descript.txt` |
| `\![reload,ghost]` | ゴースト全体 |

里々や YAYA の辞書を直しただけなら、`\![reload,shiori]` がいちばん手早い方法です。

## さくらスクリプトを直接実行する

**スクリプト入力**（開発用パレットのボタン、または Ctrl + S）を使うと、入力欄に書いたさくらスクリプトをその場でゴーストに実行させられます。表情やバルーンの見え方を試すのにぴったりです。

```text
\0\s[5]テストだよ。\w8\1\s[10]オレはぴーすけだぴ。\e
```

> **注意**
> ここに入力できるのは **さくらスクリプト** だけです。里々や YAYA の辞書の書き方はそのままでは動きません。

イベントの反応を試すこともできます。`\![raise,イベント名,r0,r1,…]` は、指定したイベントを SHIORI に送るタグで、後ろの値は `Reference0` から順に入ります。たとえば、ことねの頭（当たり判定 `Head`）をダブルクリックしたことにするには、次のように書きます。

```text
\![raise,OnMouseDoubleClick,0,0,0,0,Head,0]
```

`Reference3` が 0（\0 側）、`Reference4` が `Head` になります。実際に何度もクリックしなくても、反応のトークを確かめられます。

**スクリプトログ**（Ctrl + L）には、ゴーストが実際にしゃべったスクリプトの履歴が残ります。気になったトークを選んで「コピー」すると、中身のタグを確かめられ、「実行」でもう一度しゃべらせることもできます。

## SHIORI のエラーを見つける

「起動しない」「何もしゃべらない」「反応がおかしい」というときは、次の順に調べます。

### 1. SSP のエラーログを見る

開発用パレットの「エラーログを表示」か、スクリプトログの左下の切り替えで **エラーログ** を開きます。エラーにはレベルがあります。

| レベル | 意味 |
| --- | --- |
| Critical | 重大。起動できない・止まるなどにつながる。すぐ直す |
| Error | 誤りがあり、一部が読み飛ばされている。直す必要がある |
| Warning | 軽い誤り。SSP が補って動いているが、できるだけ直す |
| Notice | 誤りかもしれない箇所 |
| Info | 開発者向けの参考情報 |

`descript.txt` や `surfaces.txt` の書き間違い、存在しないファイルの指定などは、ここに出ることが多いです。

### 2. SHIORI とのやりとりを記録する

開発用パレットで「SHIORI呼出ログ有効」をオンにすると、SSP が SHIORI に送った依頼と、SHIORI の返事が `ghost/master/ssp_SHIORI_log.txt` に記録されます。

- 送ったイベント（`ID: OnMouseDoubleClick` など）と `Reference` の中身が正しいか。
- 返事が `204 No Content`（何も返さなかった）になっていないか。

を見ると、「イベントは届いているのに辞書が反応していない」のか、「そもそも思ったイベントが来ていない」のかを切り分けられます。

> **注意**
> このログは放っておくとどんどん大きくなります。調べ終わったらオフにし、配布物には含めないようにしましょう（第15章）。

### 3. SHIORI 自身のログを見る

里々や YAYA には、辞書の読み込みエラーなどを記録する独自のしくみがあります。開発用パレットの「SHIORI内部ログ機能有効」は、そのオン・オフを SHIORI に知らせるスイッチです（SHIORI 側が対応している場合に働きます）。具体的な見方は、里々は [第9章](09-satori-practice.md)、YAYA は [第11章](11-yaya-practice.md) を参照してください。

## 配布前のチェックリスト

最後に、配布前に確かめたいことをまとめます。印刷して、ひとつずつ印を付けていきましょう。

**起動と終了**

- [ ] SSP を起動し直して、はじめてのゴーストが起動し、あいさつする。
- [ ] 右クリックメニューから終了すると、終了のあいさつをしてから閉じる。
- [ ] エラーログに Critical・Error が出ていない（Warning もできるだけ直す）。

**見た目**

- [ ] 会話で使っている `\s[番号]` の絵がすべてある（「サーフィスが存在しない時に非表示とする」をオンにして通しで確認）。
- [ ] 瞬き・口パクが自然に動く。
- [ ] 当たり判定の位置と名前が、辞書の反応と合っている。
- [ ] 「SSPデフォルト+」以外のバルーンでも、文字があふれたり読みにくくなったりしない。

**反応**

- [ ] 頭・顔などをなでる、ダブルクリックするとそれぞれ反応する。
- [ ] 時間帯や日付で変わるトークを「現在時刻の仮想的変更」で確かめた。
- [ ] ランダムトークを長めに流して、変な組み合わせや誤字がない。

**ファイル**

- [ ] `descript.txt` の名前・作者名・`homeurl`（ネットワーク更新するなら）が正しい。
- [ ] テスト用の辞書、ログファイル、セーブデータなどを配布物から外した。
- [ ] `readme.txt` を書いた。

## まとめ

- 本体設定「一般」の「開発者用機能を有効にする」をオンにすると、開発用の機能が使える。
- 開発用パレットには、当たり判定の表示、スクリプト入力、サーフィステスト、リロードなどがまとまっている。
- 書き換えたら読み直す。辞書だけなら `\![reload,shiori]` が手早い。
- スクリプト入力ではさくらスクリプトを直接実行でき、`\![raise,…]` でイベントも試せる。
- エラーはまず SSP のエラーログ、次に SHIORI 呼出ログ、最後に SHIORI 自身のログで探す。

## 練習問題

1. 辞書に新しいトークを書き足したのに、ゴーストがしゃべってくれません。最初に試すことは何でしょう。
2. ぴーすけ（\1 側）の体（`Body`）をダブルクリックしたときの反応を、スクリプト入力で試すにはどう書けばよいでしょう。
3. 「夜11時のトーク」を、夜まで待たずに確かめるにはどうすればよいでしょう。

<details>
<summary>答えとヒント</summary>

1. 辞書を読み直します。開発用パレットの「リロード」か、スクリプト入力で `\![reload,shiori]` を実行します。それでもだめならエラーログを確認しましょう。
2. `\![raise,OnMouseDoubleClick,0,0,0,1,Body,0]`。`Reference3` を 1 にすると \1 側になります。
3. 開発用パレットの「現在時刻の仮想的変更」で、SSP の時刻を夜11時ごろにします。終わったら「Reset」で元に戻します。

</details>
