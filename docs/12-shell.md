# 第12章 シェルを作る

## この章で学ぶこと

- シェルを作る画像（サーフェス）の名前と番号の決まり
- シェルの `descript.txt` に書く主な項目
- `surfaces.txt` で当たり判定・パーツの合成・アニメーションを書く方法
- 当たり判定の名前が SHIORI のマウスイベントに届くしくみ
- 着せ替えのあらましと、画像の用意のしかた

ここまでの章で、ことねとぴーすけはたくさん話せるようになりました。この章では、二人の「見た目」である **シェル**（ゴーストの立ち絵一式）を作ります。シェルは `hajimete/shell/master/` フォルダに入っています。シェルの全体像は UKADOC の [シェルの作成](https://ukatech.shillest.net/ukadoc-spec/dev/shell/) にもまとまっているので、あわせて読むと理解が深まります。

## シェルのフォルダの中身

最低限のシェルは、次のようなファイルでできています。

```text
hajimete/
  shell/
    master/
      descript.txt   … シェルの名前や作者などの基本情報
      surfaces.txt   … 当たり判定・合成・アニメーションの設定
      surface0.png   … \0 側（ことね）の基本の絵
      surface10.png  … \1 側（ぴーすけ）の基本の絵
      readme.txt     … シェルの説明（省略可）
      thumbnail.png  … シェル選択メニューに出る見本画像（省略可）
```

`descript.txt` は必須です。これがないとシェルとして認識されません。`surfaces.txt` は、画像を置くだけで足りるなら省略してもかまいませんが、実際にはほぼ必ず使います。

## サーフェス画像を用意する

### サーフェスとは

**サーフェス** とは、シェルの絵の1枚1枚のことです。表情ごとの立ち絵や、アニメーションの1コマも、すべてサーフェスとして番号で管理されます。さくらスクリプトの `\s[1]` は「1番のサーフェスに切り替える」という意味でした（第6章）。

サーフェスは、次のどちらかの方法で用意します。

- `surface番号.png` という名前の画像を置く（例：`surface0.png`、`surface5.png`）
- `surfaces.txt` で複数の画像を合成して作る（後で説明する `element`）

`surface0000.png` のように 0 を詰めた名前も `surface0.png` と同じに扱われます。画像の形式は PNG が基本です。SSP では WebP など PNG 以外の形式も読めます（対応形式の一覧は SSP ヘルプの「画像ビューワ」のページにあります）が、この本では PNG を使います。大きさや色数に制限はありません。

### 番号の決まりと慣例

番号は 0 以上なら基本的に自由ですが、次の2つは特別です。

- `surface0` … \0 側（メインキャラクター）の基本サーフェス
- `surface10` … \1 側（サブキャラクター）の基本サーフェス

この2枚は基本的に必須とされています（SSP では必須ではなく推奨）。キャラクターが一人だけのゴーストでも、全面を抜き色で塗った `surface10.png` を置いておくのが無難です。

それ以外の番号は作者が決めます。\0 側の表情を 0 番台、\1 側を 10 番台にまとめておくと迷いません。この本の「はじめてのゴースト」では、たとえば次のように割り当てます。

| 番号 | 中身 |
| --- | --- |
| 0 | ことね・通常 |
| 1 | ことね・照れ |
| 2 | ことね・驚き |
| 5 | ことね・笑顔 |
| 10 | ぴーすけ・通常 |
| 11 | ぴーすけ・別の表情（驚いたり、むっとしたりするとき） |
| 100, 101 | ことねの瞬き用パーツ（半目・閉じ目） |
| 200, 201 | ことねの口パク用パーツ |

大事なのは、**会話で使っている `\s[番号]` と、絵の番号がそろっていること** です。第6章以降の会話で使った番号を書き出して、全部の絵がそろっているか確かめましょう。

### 透過のしかた

デスクトップに立ち絵だけを表示するには、背景を透明にする必要があります。方法は3つあります。

1. **抜き色（透過色）**：画像の左上の1ドット（座標 0,0）と同じ色の部分が透明になります。キャラクターの中に同じ色があると、そこも抜けてしまうので、キャラクターに使わない色を選びます。輪郭がぼかしてあると、背景色と混ざったふちが残るので、ふちはくっきり描きます。
2. **PNA ファイル**：透明度をグレースケールで描いた PNG を、拡張子だけ `.pna` に変えたものです。`surface0.png` には `surface0.pna` を組み合わせます。白が不透明、黒が透明、その中間が半透明です。
3. **アルファチャンネル付き PNG（SSP のみ）**：シェルの `descript.txt` に `seriko.use_self_alpha,1` と書くと、PNG 自体の透明度がそのまま使われます。ペイントソフトで背景を透明にして保存するだけなので、いちばん手軽です。

> **注意**
> 半透明の部分もクリックの対象になります。透明にしたいところは「完全に」透明（PNA なら真っ黒）にしておきましょう。

## シェルの descript.txt

シェルの基本情報を書くファイルです。必須なのは `type` と `name` だけですが、作者情報も書いておきましょう。

`shell/master/descript.txt`

```text
charset,UTF-8
type,shell
name,はじめてのゴースト 標準シェル
craftman,yourname
craftmanw,あなたの名前

seriko.use_self_alpha,1

sakura.balloon.offsetx,0
sakura.balloon.offsety,0
kero.balloon.offsetx,0
kero.balloon.offsety,0
```

| 項目 | 意味 |
| --- | --- |
| `charset` | 文字コード。必ず1行目。古い環境との互換を気にしないなら UTF-8 が推奨されています |
| `type` | `shell` と書く |
| `name` | シェルの名前。シェル切り替えメニューに出ます |
| `craftman` / `craftmanw` | 作者名（英数字）／作者名（日本語可） |
| `craftmanurl` | 作者の Web サイト（省略可） |
| `seriko.use_self_alpha` | SSP で PNG の透明度を使うなら `1` |
| `sakura.balloon.offsetx` など | バルーン（吹き出し）の表示位置の調整。`sakura` が \0 側、`kero` が \1 側 |
| `homeurl` | SSP では、シェル単体のネットワーク更新用 URL（第15章） |

バルーン位置は、x を増やすとキャラクター寄りに、y を増やすと下にずれます。マイナスにすると逆方向です。実際に表示しながら少しずつ調整しましょう。

## surfaces.txt の書き方

`surfaces.txt` は、サーフェスごとの当たり判定・合成・アニメーションを書くファイルです。

### 基本の形

`shell/master/surfaces.txt`

```text
charset,UTF-8

descript
{
version,1
}

surface0
{
// ここに surface0 の設定を書く
}
```

決まりは次のとおりです。

- `charset` を書くなら必ず1行目。
- 設定は `{` と `}` で囲んだ **ブレス**（かたまり）の中に書きます。`{` と `}` は、それだけの行にします。`surface0 {` のように同じ行に続けて書くことはできません。
- 設定として読めない行はコメント扱いです。慣例として `//` で始めます。
- `descript` ブレスの `version,1` は、アニメーションを新しい書式（SERIKO/2.0）で書くという宣言です。この章の書き方はすべて新しい書式なので、必ず入れてください。
- SSP では、`surfaces2.txt` のように `surfaces` で始まる別ファイルも追加で読み込まれます。

### collision：当たり判定

**当たり判定** は、マウスで「頭」「顔」などを触ったことを見分けるための領域です。

```text
surface0
{
collision0,60,20,140,70,Head
collision1,70,75,130,120,Face
collision2,65,150,135,220,Bust
}
```

`collision番号,左上X,左上Y,右下X,右下Y,名前` の順に書きます。座標は画像の左上を 0,0 とした値です。番号は同じサーフェスの中で重ならないようにします。同じ名前を何行も書いてもかまいません（左右の手を両方 `Hand` にする、など）。

SSP では、`collisionex` を使うと長方形以外の形も書けます。

```text
collisionex3,Head,ellipse,60,20,140,70
collisionex4,Hand,polygon,20,200,50,190,60,230
```

形は `rect`（長方形）、`ellipse`（楕円）、`circle`（円）、`polygon`（多角形）などから選びます。

#### 当たり判定の名前は SHIORI に届く

ここがゴースト作りでいちばん大事なつながりです。ユーザーがキャラクターをクリックやダブルクリックすると、SSP は `OnMouseClick` や `OnMouseDoubleClick` などのイベントを SHIORI に送ります。そのとき、

- `Reference3` に「どのキャラクターか」（\0 側なら 0、\1 側なら 1）
- `Reference4` に「当たり判定の名前」（ここで書いた `Head` など）

が入ります。マウスを動かしたときの `OnMouseMove` でも同じです。つまり、ここで付けた名前を使って「ことねの頭をなでたら照れる」といった反応を書けます。里々での書き方は第9章、YAYA では第11章で扱っています。**名前は大文字・小文字まで一字一句そろえる** 必要があるので、シェルを作ったら名前の一覧をメモしておきましょう。

### element：パーツを合成する

表情ごとに全身の絵を描くのは大変です。`element` を使うと、体と顔などのパーツ画像を重ねて1枚のサーフェスにできます。

```text
surface5
{
element0,overlay,body.png,0,0
element1,overlay,face_smile.png,0,0
}
```

`element番号,描画方法,ファイル名,X座標,Y座標` の順です。番号は 0 から始まる連番で、小さい番号ほど奥に描かれます。`overlay` は「上に重ねる」描画方法です。ファイル名は好きな名前の PNG でかまいません。この場合 `surface5.png` は不要です。

`element` は `surface0` や `surface10` でも使えますが、ゴーストのプレビュー画像を作るサービスなどでは、この2枚が普通の PNG のほうが扱いやすいとされています。基本の2枚は1枚絵にしておくと安心です。

### animation：瞬きと口パク

シェルのアニメーションのしくみを **SERIKO** と呼びます。1つのアニメーションは、「いつ動くか」を書く `interval` の行と、コマを並べる `pattern` の行でできています。

```text
surface0
{
collision0,60,20,140,70,Head
collision1,70,75,130,120,Face
collision2,65,150,135,220,Bust

// 瞬き
animation0.interval,sometimes
animation0.pattern0,overlay,100,50,85,90
animation0.pattern1,overlay,101,50,85,90
animation0.pattern2,overlay,100,50,85,90
animation0.pattern3,overlay,-1,50,0,0

// 口パク
animation10.interval,talk,2
animation10.pattern0,overlay,200,80,95,110
animation10.pattern1,overlay,201,80,95,110
animation10.pattern2,overlay,-1,80,0,0
}
```

`animation番号.pattern番号,描画方法,サーフェス番号,待ち時間,X,Y` の意味は次のとおりです。

- **サーフェス番号**：このコマで重ねる絵（ここでは目のパーツ `surface100.png` など）。`-1` は「アニメーションをやめて元の絵に戻す」。
- **待ち時間**：このコマを表示する **までの** 時間（ミリ秒）。そのコマを見せる長さではない点に注意。
- **X, Y**：パーツを重ねる位置（右・下が正）。上の例では、目のパーツを (85,90) の位置に重ねています。数字は絵に合わせて変えてください。

`interval` の行は必ず `pattern` より先に、続けて書きます。`pattern` の番号は 0 から抜けなく並べます。

アニメーションの番号（`animation0` の 0）は自由ですが、**同じ意味のアニメーションには、どのサーフェスでも同じ番号を付けます**。surface1 にも瞬きを付けるなら、それも `animation0` にします。着せ替えでは特にこの決まりが必須です。

#### interval の種類

| interval | 動くタイミング |
| --- | --- |
| `sometimes` | そのサーフェスの間、毎秒 1/2 の確率 |
| `rarely` | 毎秒 1/4 の確率 |
| `random,数値` | 毎秒「1/数値」の確率 |
| `periodic,数値` | 数値秒ごと（SSP） |
| `always` | ずっとくり返す |
| `runonce` | そのサーフェスに切り替わった瞬間に1回 |
| `talk,数値` | バルーンに文字が出ている間、数値文字ごと（口パク向き） |
| `yen-e` | さくらスクリプトの `\e` が来たとき |
| `never` | 自動では動かない。`\i[番号]` などで呼び出す |
| `bind` | 着せ替え（次の節） |

瞬きには `sometimes` か `rarely`、口パクには `talk` が定番です。`never` にしたアニメーションは、会話の中で `\i[番号]` と書いて好きなときに動かせます。

## 着せ替え（bind）のあらまし

**着せ替え** は、服やアクセサリーの表示・非表示を切り替えるしくみです。伺かでは、`interval` が `bind` のアニメーションとして書きます。コマ送りはされず、オンのあいだ常に重ねて表示されます。

`shell/master/surfaces.txt`（追記）

```text
surface0
{
animation20.interval,bind
animation20.pattern0,add,300,0,90,10
}
```

`shell/master/descript.txt`（追記）

```text
sakura.bindgroup20.name,アクセサリ,リボン
sakura.bindgroup20.default,1
sakura.menuitem0,20
```

- `sakura.bindgroup番号.name,カテゴリ名,パーツ名` の番号は、`surfaces.txt` のアニメーション番号（ここでは 20）と同じにします。
- `.default,1` で最初からオンになります。
- `sakura.menuitem0,20` で、右クリックメニューの「着せ替え」に表示します。\1 側は `kero.` で始めます。
- リボンを見せたい **すべてのサーフェス** に、同じ番号 20 で定義を書きます。

SSP では、さくらスクリプトの `\![bind,アクセサリ,リボン,0]` で外し、`1` で着けることもできます。詳しくは UKADOC の [着せ替えの設定](https://ukatech.shillest.net/ukadoc-spec/dev/bind/) を見てください。

## 画像の用意のしかた

絵の用意には、おもに3つの道があります。

- **自分で描く**：ペイントソフトで、透明な背景にキャラクターを描き、PNG で保存します。最初は「通常」と「笑顔」の2表情、ぴーすけ1枚からで十分です。体と顔を別レイヤーにしておくと、`element` で表情差分を作るのが楽になります。
- **フリーシェルを使う**：自由に使ってよいと公開されているシェルを **フリーシェル** と呼びます。UKADOC や SSP ヘルプでは、探し先として「freeshell wiki」が紹介されています。必ず配布元の利用条件を読み、クレジットの書き方や改変の可否を守ってください（第15章）。
- **絵の得意な人に頼む**：依頼するときは、必要な番号と表情の一覧を表にして渡すと話が早いです。

当たり判定の座標を調べるには、画像編集ソフトでカーソル位置の座標を読むのが手軽です。UKADOC では、画像の上をドラッグすると座標をコピーしてくれる「Coordin」というツールも紹介されています。

## SSP で確かめる

書いたら、すぐに SSP で確かめます。第14章で詳しく説明する **開発用パレット** を使うと便利です。

1. 右クリックメニューの「設定」→「本体設定」→「一般」で「開発者用機能を有効にする」をオンにする。
2. 右クリックメニューの「機能」から「開発用パレット」を開く（Ctrl + Shift + D）。
3. 「リロード」でシェルを読み込み直す。
4. 「当たり判定を表示」にチェックを入れ、名前つきの枠が正しい位置にあるか見る。
5. 「サーフィステスト」で、サーフェスを1枚ずつ切り替え、アニメーションを1つずつ動かしてみる。

## まとめ

- サーフェスは `surface番号.png`。`surface0` が \0 側、`surface10` が \1 側の基本。
- 透過は「左上の色」「PNA」「アルファ付き PNG（SSP、`seriko.use_self_alpha,1`）」の3通り。
- シェルの `descript.txt` は `type,shell` と `name` が必須。バルーン位置もここで調整する。
- `surfaces.txt` は `descript` ブレスに `version,1` を書き、`surface番号` のブレスに設定を書く。
- `collision` の名前は、マウスイベントの `Reference4` として SHIORI に届く。
- `element` でパーツ合成、`animation` で瞬き（`sometimes`）や口パク（`talk`）。同じ意味には同じ番号。
- 着せ替えは `interval` が `bind` のアニメーションと、`descript.txt` の `bindgroup` で作る。

## 練習問題

1. ぴーすけの `surface10` に、頭（`Head`）と体（`Body`）の当たり判定を書いてください。
2. ことねの口パクを、3文字ごとに動くように変えるにはどこを直せばよいでしょう。
3. `surface0.png` の背景が透明にならず、四角い色が残ってしまいます。考えられる原因を2つ挙げてください。

<details>
<summary>答えとヒント</summary>

1. 例：
   ```text
   surface10
   {
   collision0,20,10,80,50,Head
   collision1,15,50,85,110,Body
   }
   ```
   座標は絵に合わせて変えます。開発用パレットの「当たり判定を表示」で確かめましょう。
2. `animation10.interval,talk,2` の `2` を `3` にします。
3. たとえば「左上の1ドットの色と背景の色が違う」「アルファ付き PNG を使っているのに `seriko.use_self_alpha,1` を書いていない（または `descript.txt` をリロードしていない）」など。

</details>
