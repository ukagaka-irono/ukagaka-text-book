## YAYA ってどんな SHIORI？

**YAYA**（やや）は、C 言語に似た書き方をする SHIORI です。辞書は「関数」の集まりで、`OnBoot { … }` のように **イベント名と同じ名前の関数** を書いておくと、そのイベントが起きたときに呼ばれます。

里々が「台本を書く」感覚なのに対し、YAYA は「小さなプログラムを書く」感覚に近いのが特徴です。条件分岐や計算、配列などがそろっているので、凝った仕掛けを作りたくなったときに力を発揮します。とはいえ、セリフを並べるだけなら難しいことはありません。この章ではまず「動かす」「しゃべらせる」ところまでを目指します。

公式の説明書は [YAYA ドキュメント](https://yaya-shiori.github.io/yaya-docs/) にあります。この章で出てくる文法の細かいところは、そちらで確かめられます。

## YAYA を動かすのに必要なもの

### 4 つの部品

YAYA のゴーストは、次の 4 つがそろって初めて動きます。どれも `ghost/master` フォルダに置きます。

| 部品 | ファイル | 役割 |
| --- | --- | --- |
| YAYA 本体 | `yaya.dll` | 辞書を読んで実行するプログラム |
| 基礎設定ファイル | `yaya.txt` | 文字コードや、読み込む辞書の一覧を書く |
| システム辞書 | `yaya_base` フォルダ | YAYA を「SHIORI として」動かすための辞書 |
| 自分の辞書 | `dic_boot.dic` など | ゴーストのセリフや反応を書く |

基礎設定ファイルの名前は「DLL の名前 + `.txt`」と決まっています。`yaya.dll` なら `yaya.txt` です。

### システム辞書とは

ここが YAYA でいちばん誤解されやすいところです。

`yaya.dll` そのものは、「文字列を受け取って、辞書のプログラムを実行して、文字列を返す」だけの汎用の道具です。ベースウェアから届く SHIORI のリクエスト（第7章で見た `GET SHIORI/3.0` で始まる文字列）を読み解いて `OnBoot` 関数を呼ぶ、という SHIORI らしい仕事は、実は YAYA の言葉で書かれた **システム辞書** が受け持っています。

システム辞書の中心は `shiori3.dic` で、主に次のことをしてくれます。

- リクエストの `ID` を見て、同じ名前の関数（`OnBoot` など）を呼ぶ
- `Reference0` などの値を、変数 `reference[0]` などに入れておく
- 関数が返した文字列を、SHIORI のレスポンスの形にしてベースウェアへ返す
- 一定時間ごとに `OnAiTalk` 関数を呼んで、ランダムトークをさせる
- 時刻を表す `hour` や `minute` など、便利な変数を用意する

つまり、**システム辞書がないと YAYA はゴーストとして動きません**。なお、YAYA 本体が直接呼ぶ `load`・`unload`・`request` といった関数はシステム辞書の中で定義されているので、自分の辞書で同じ名前の関数を作ってはいけません（YAYA では、同じ名前の関数が 2 つあるとエラーになります）。

> **コラム：テンプレートゴーストから始める方法**
> YAYA では、システム辞書や設定一式があらかじめ入った **テンプレートゴースト** を改造して作り始めるのが定番です。「はろーYAYAわーるど（紺野ややめ）」「SimpleYAYAテンプレート」などがあり、[YAYA でゴーストを作る](https://yaya-shiori.github.io/yaya-docs/startup/creating-ghost/) で紹介されています。テンプレートはとても便利ですが、最初からたくさんのファイルが入っているぶん、どこが何なのか見えにくくなります。この本では、しくみを理解するために、システム辞書だけを入れて残りは自分で書く方法をとります。

### 入手して置く

1. [yaya-shiori のリリースページ](https://github.com/YAYA-shiori/yaya-shiori/releases) から最新版の zip（執筆時点では `yaya.zip`）をダウンロードして展開し、`yaya.dll` を取り出します。
2. システム辞書の置き場所である [yaya-dic](https://github.com/YAYA-shiori/yaya-dic) のページを開き、「Code」→「Download ZIP」でダウンロードして展開します。
3. 展開した中の `yaya_base` フォルダを、フォルダごと `ghost/master` にコピーします。中に `shiori3.dic`・`config.dic`・`_loading_order.txt` などがあれば正しく置けています。
4. `yaya.dll` も `ghost/master` にコピーします。

`yaya.dll` とシステム辞書は、なるべく新しいもの同士を組み合わせてください。片方だけ古いと、うまく動かないことがあります。

置き終わると、ゴーストのフォルダは次のようになります（シェルの用意のしかたは第12章で説明します）。

```text
hajimete/
├─ install.txt
├─ readme.txt
├─ ghost/
│   └─ master/
│       ├─ descript.txt
│       ├─ yaya.txt
│       ├─ yaya.dll
│       ├─ yaya_base/        ← システム辞書（中身はいじらない）
│       ├─ dic_boot.dic      ← ここから下を自分で書く
│       └─ dic_talk.dic
└─ shell/
    └─ master/
```

この章と次の章で作る辞書の完成形は [`samples/yaya/hajimete/`](../samples/yaya/hajimete/) にあります。`yaya.dll` と `yaya_base` は同梱していないので、上の手順で入れてください。

## descript.txt で YAYA を指定する

第5章で書いた `descript.txt` に、使う SHIORI の DLL 名を `shiori` で指定します。指定しないと `shiori.dll` を探しにいくので、YAYA では必ず書きます。

`ghost/master/descript.txt`

```text
charset,UTF-8
type,ghost
name,はじめてのゴースト
sakura.name,ことね
kero.name,ぴーすけ
craftman,yourname
craftmanw,あなたの名前
shiori,yaya.dll
```

`craftman` は半角英数字だけで書く決まりなので、日本語の作者名は `craftmanw` に書きます。

## yaya.txt を書く

`yaya.txt` は「どの文字コードで」「どの辞書を」読むかを YAYA に教えるファイルです。1 行に 1 つ、「項目, 値」の形で書きます。`//` から行末まではコメントです。

`ghost/master/yaya.txt`

```text
// yaya.txt : basic settings for "Hajimete no Ghost" (YAYA version)
// Keep this file ASCII only.

charset, UTF-8

dicdir, yaya_base

dic, dic_boot.dic
dic, dic_talk.dic
```

| 行 | 意味 |
| --- | --- |
| `charset, UTF-8` | 辞書・入出力・セーブファイルなどの文字コードをまとめて UTF-8 にする。書かないと Shift_JIS 扱いになる |
| `dicdir, yaya_base` | `yaya_base` フォルダの中身をシステム辞書として読む。フォルダ内の `_loading_order.txt` に従って、決まった順で読み込まれる |
| `dic, ファイル名` | 自分の辞書を 1 つ読む。辞書を増やしたら、そのたびに 1 行足す |

書くときの注意が 3 つあります。

- **`yaya.txt` には日本語を書かない。** このファイル自体は、OS の標準の文字コードで読まれます。半角英数字だけで書いておけば、どの環境でも同じように読めます。コメントも英語か、なしにしておきましょう。
- **`dicdir, yaya_base` は自分の辞書より先に書く。** システム辞書には、ほかの辞書より先に読み込まれる必要がある設定が含まれています。
- **`dic` に書いたファイルが存在しないとエラーになる。** 次の章で辞書を増やすときは、ファイルを作ってから行を足してください。

辞書ファイル（`.dic`）は、`charset` に合わせて **UTF-8** で保存します。

## はじめての辞書

いよいよ自分の辞書です。まずは起動と終了のあいさつだけを書いてみます。

`ghost/master/dic_boot.dic`

```c
// 起動したとき
OnBoot
{
	"\1\s[10]\0\s[0]こんにちは、ユーザーさん。\w9\1今日もよろしくだぴ。\e"
	"\1\s[10]\0\s[0]あ、ユーザーさん！\w9\1待ってたぴ。\e"
}

// 終了するとき（最後に \- を書く）
OnClose
{
	"\1\s[10]\0\s[0]またね、ユーザーさん。\w9\1おやすみだぴ。\w9\-"
}
```

`OnClose` の最後の `\-` は「ゴーストを終了する」さくらスクリプトです。`OnClose` で返すセリフにこれを書き忘れると、あいさつだけしてゴーストが終わらなくなります。

動作を確かめましょう。

1. `dic_boot.dic` と、中身が空の `dic_talk.dic` を `ghost/master` に作り、UTF-8 で保存します。
2. SSP のゴースト切り替えメニューから「はじめてのゴースト」を選びます。
3. ことねとぴーすけのあいさつが出れば成功です。何度か切り替え直すと、2 つのセリフのどちらかがランダムに出るのがわかります。
4. 辞書を書き換えたら、SSP の **開発用パレット**（右クリックメニューの「機能」から開く。開発者用機能を有効にしておく必要があります）の「リロード」で読み込み直すか、ゴーストを切り替え直します。

> **注意**
> 何もしゃべらない、反応しないときは、辞書のどこかに書きまちがいがある可能性が高いです。辞書の読み込みでエラーが起きると、YAYA は何も返さない状態になります。調べ方は第11章の「よくあるつまずき」で説明します。

## 関数と候補

### 関数の形

YAYA の関数は、名前のあとに `{ }` を書き、その中に中身を書きます。

```c
関数名
{
	中身
}
```

関数名には日本語も使えます。ただし、数字や `_` で始まる名前、記号を含む名前、YAYA の予約語と同じ名前は使えません。また、**同じ名前の関数を 2 つ書くとエラー** になります。

### 候補はランダムに 1 つ選ばれる

関数の中に文字列を 1 行に 1 つずつ並べると、それぞれが **出力候補** になります。関数が呼ばれると、候補の中から 1 つがランダムに選ばれて返されます。さっきの `OnBoot` で 2 つのセリフが入れ替わったのはこのためです。

候補は必ず 1 行に 1 つ書きます。`"A" "B"` のように 1 行に並べるとエラーです。

### 選び方を変える

関数名のうしろに `: 選び方` をつけると、選び方を変えられます。

| 書き方 | 動き |
| --- | --- |
| （なし） | 毎回ランダム。同じものが続くこともある |
| `: nonoverlap` | なるべく前回と同じ候補を選ばない |
| `: sequential` | 上から順番に返し、最後まで行ったら最初に戻る |

ランダムトークのように「同じ話が続くと不自然」なものには `nonoverlap` が向いています。

### 出力確定子 `--`

1 行に `--` だけを書くと、そこで候補が区切られます。区切られたグループごとに 1 つずつ選ばれ、それらがつながって 1 つの結果になります。この `--` を **出力確定子** といいます。

```c
OnBoot
{
	"\1\s[10]\0\s[0]"
	--
	"こんにちは、ユーザーさん。"
	"あ、ユーザーさん！"
	--
	"\w9\1"
	--
	"今日もよろしくだぴ。\e"
	"待ってたぴ。\e"
}
```

この `OnBoot` は「あいさつ 2 通り × ぴーすけの返事 2 通り」で 4 通りの組み合わせを作ります。毎回書いていた `\1\s[10]\0\s[0]` も 1 回で済みます。

### 自分で関数を作る

候補の行には、文字列だけでなく **関数名** も書けます。その関数を呼んだ結果が候補になります。

```c
OnAiTalk
{
	おやつトーク
}

おやつトーク
{
	"\1\s[10]\0\s[0]今日のおやつは"
	--
	"いちごのショートケーキ"
	"みたらし団子"
	"ポテトチップス"
	--
	"がいいなあ。\w9\1"
	--
	"オレの分もよろしくだぴ。\e"
	"オレはひまわりの種で十分だぴ。\e"
}
```

セリフの部品を関数に分けておくと、いろいろな場所から使い回せます。

## 文字列と埋め込み

### 2 種類の引用符

YAYA の文字列には 2 種類あります。

| 書き方 | 埋め込み |
| --- | --- |
| `"…"`（ダブルクォート） | `%(…)` を展開する |
| `'…'`（シングルクォート） | 展開しない。書いたとおりの文字列 |

ダブルクォートの文字列の中に `"` そのものを入れたいときは、`""` と 2 つ重ねます。

### `%( )` で埋め込む

ダブルクォートの文字列の中に `%(…)` と書くと、カッコの中の変数や関数、計算式を実行して、その結果をその場所に埋め込みます。

```c
ことねの好きなもの
{
	"日なたぼっこ"
	"いちごのショートケーキ"
	"ユーザーさんとのおしゃべり"
}

OnAiTalk
{
	"\1\s[10]\0\s[0]わたしの好きなもの？\w9\n\nうーん……%(ことねの好きなもの)かな。\e"
	"\1\s[10]\0\s[0]いま%(hour)時%(minute)分。\w9\n\nユーザーさん、ちょっと休憩しない？\e"
}
```

`hour`（時）と `minute`（分）は、システム辞書が用意している時刻の値です。ほかに `year`・`month`・`day` や、ゴーストの累計起動回数 `ghostuptimes` などもあります（[yaya_shiori3.dic の説明](https://yaya-shiori.github.io/yaya-docs/system/yaya-shiori3-dic/)）。

`%(…)` のカッコの中には `"` を書けません。文字列を含む式を埋め込みたいときは、`"…" + 式 + "…"` のように `+` でつなぎます。

### 長い文字列を折り返す

文字列の途中で改行するとエラーになります。長いセリフを複数行に分けたいときは、行末に `/` を書きます。次の行の行頭の空白やタブは取り除かれて、前の行にくっつきます。

```c
OnAiTalk
{
	"\1\s[10]\0\s[0]ユーザーさんのデスクトップ、/
	けっこうにぎやかだね。\e"
}
```

## 変数

**変数** は、値を入れておく名前つきの箱です。`名前 = 値` で値を入れ（**代入**）、名前を書けば中身を取り出せます。宣言は要りません。

```c
OnBoot
{
	あいさつ回数 += 1
	"\0\s[0]これで%(あいさつ回数)回目のあいさつだね。\e"
}
```

`+= 1` は「1 増やす」という意味です。まだ一度も代入していない変数は、計算では 0、文字列では空として扱われます。なお、代入の行は出力候補にはなりません。

YAYA の変数は名前で 2 種類に分かれます。

| 種類 | 名前 | 使える範囲 | 保存 |
| --- | --- | --- | --- |
| **ローカル変数** | `_` で始まる（`_目` など） | その `{ }` の中だけ。抜けると消える | されない |
| **グローバル変数** | `_` で始まらない（`あいさつ回数` など） | どの関数からでも | 終了時に自動で保存され、次の起動で戻る |

グローバル変数は `ghost/master/yaya_variable.cfg` に保存されます。ずっと覚えておく必要のない値は、ローカル変数にしておくとセーブファイルが散らかりません。

```c
サイコロトーク
{
	_目 = RAND(6) + 1
	"\1\s[10]\0\s[0]サイコロ振るよ、えいっ。\w9\w9\n\n……%(_目)が出たよ！\w9\1次はオレの番だぴ。\e"
}
```

`RAND(6)` は 0〜5 のどれかを返す組み込み関数なので、`+ 1` して 1〜6 にしています。

値には整数・実数・文字列などの **型** があります。`1` は数値、`"1"` は文字列で、`1 + 1` は `2` ですが `"1" + "1"` は `"11"` になります。

## さくらスクリプトとの組み合わせ

YAYA の辞書では、さくらスクリプト（第6章）は **ただの文字列** です。必ず `"…"` か `'…'` で囲みます。囲み忘れると、変数名や関数名だと思われてしまいます。

YAYA の文字列は `\` を特別扱いしないので、`\0`・`\s[0]`・`\n`・`\w9`・`\e` は書いたとおりにベースウェアへ届きます。`\\` のように重ねる必要はありません。

この本のサンプルでは、トークの頭に `\1\s[10]\0\s[0]` を置いて、ぴーすけとことねの表情を通常に戻してから話し始めるようにしています。表情の番号は、ことねが `\s[0]`（通常）・`\s[1]`（照れ）・`\s[2]`（驚き）・`\s[5]`（笑顔）、ぴーすけが `\s[10]`（通常）・`\s[11]`（別の表情）です（第12章）。

> **注意**
> ダブルクォートの文字列では `%` が埋め込みの合図になります。セリフに `%` を書くと、思わぬ値に置き換わることがあります。`%` を含む文字列は、シングルクォートで書くと安全です。

開発用パレットの「スクリプト入力」を使うと、さくらスクリプトをその場で試せます。辞書に書く前にここで見た目を確かめると、手戻りが減ります。

## ランダムトークを 10 個書く

### OnAiTalk とトーク間隔

ランダムトークは `OnAiTalk` という関数に書きます。`OnAiTalk` はベースウェアのイベントではなく、システム辞書が **`aitalkinterval` 秒ごと** に呼んでくれる関数です。`aitalkinterval` はグローバル変数で、初めて起動したときに 180（3 分）が入ります。間隔を変える方法は第11章で扱います。

ゴーストが話している最中や、選択肢を出している最中などは、システム辞書がランダムトークを見送ってくれます。

### dic_talk.dic

これまでに出てきた書き方を使って、10 個のトークを書きます。

`ghost/master/dic_talk.dic`

```c
// システム辞書が aitalkinterval 秒ごとに呼び出す
OnAiTalk : nonoverlap
{
	// 1
	"\1\s[10]\0\s[0]ねえぴーすけ、窓の外を見て。\w9\1……ここはデスクトップだから、窓はないぴ。\w9\0\s[1]あ、そっか。\e"

	// 2
	"\1\s[10]\0\s[0]ユーザーさんのデスクトップ、けっこうにぎやかだね。\w9\n\nアイコン、ときどき整理してあげてね。\e"

	// 3
	"\0\s[0]\1\s[10]オレ、本気を出せば空も飛べるんだぴ。\w9\0\s[2]え、飛んでるとこ見たことないよ？\w9\1\s[11]……今日は気分じゃないだけだぴ。\e"

	// 4 関数の埋め込み
	"\1\s[10]\0\s[0]わたしの好きなもの？\w9\n\nうーん……%(ことねの好きなもの)かな。\e"

	// 5 システム辞書の時刻を埋め込む
	"\1\s[10]\0\s[0]いま%(hour)時%(minute)分。\w9\n\nユーザーさん、ちょっと休憩しない？\e"

	// 6 システム辞書の変数（累計起動回数）を埋め込む
	"\1\s[10]\0\s[0]わたしたちが起動したの、これで%(ghostuptimes)回目なんだって。\w9\1数えてたのかぴ。\e"

	// 7 ローカル変数を使う関数
	サイコロトーク

	// 8
```

### 動作を確かめる

3 分待つのは大変なので、すぐに確かめる方法を使いましょう。

1. 辞書を保存し、開発用パレットの「リロード」で読み込み直します。
2. 開発用パレットの「スクリプト入力」に `\![raise,OnAiTalk]` と入力して送ります。`\![raise,イベント名]` は、自分のゴーストにイベントを起こさせるさくらスクリプトです。
3. 送るたびに、10 個のトークのどれかが出れば成功です。`nonoverlap` をつけたので、同じトークが続けて出にくくなっています。

## まとめ

- YAYA を SHIORI として動かすには、`yaya.dll`・`yaya.txt`・システム辞書（`yaya_base`）・自分の辞書の 4 つが必要。システム辞書が SHIORI のリクエストを読み解き、同じ名前の関数を呼んでくれる。
- `descript.txt` には `shiori,yaya.dll` を書く。`yaya.txt` は半角英数字だけで書き、`charset, UTF-8`、`dicdir, yaya_base`、`dic, ファイル名` の順に並べる。
- 関数の中に 1 行 1 つずつ書いた候補から、1 つがランダムに選ばれる。`: nonoverlap` で連続を避け、`--` で部品を組み合わせられる。
- ダブルクォートの文字列では `%(…)` で変数や関数を埋め込める。`_` で始まる変数はローカル、それ以外はグローバルで自動保存される。
- さくらスクリプトは文字列として書く。ランダムトークは `OnAiTalk` に書くと、`aitalkinterval` 秒ごとに呼ばれる。

## 練習問題

1. 次の `yaya.txt` には問題が 2 つあります。どこでしょう。

   ```text
   // 辞書の設定
   dic, dic_boot.dic
   dicdir, yaya_base
   ```

<details>
<summary>答え</summary>

- コメントに日本語が書かれています。`yaya.txt` は OS の標準の文字コードで読まれるので、半角英数字だけで書きます。
- `dicdir, yaya_base` が自分の辞書より後にあります。システム辞書を先に読み込むよう、順番を入れ替えます。また、辞書を UTF-8 で書くなら `charset, UTF-8` も必要です。

</details>

2. `OnBoot` を、出力確定子 `--` を使って「あいさつ 3 通り × ぴーすけの返事 3 通り」の 9 通りになるように書き直してください。

<details>
<summary>ヒント</summary>

`"\1\s[10]\0\s[0]"` → `--` → あいさつ 3 行 → `--` → `"\w9\1"` → `--` → 返事 3 行、の順に並べます。返事の最後には `\e` をつけます。

</details>

3. 次の関数は、ことねをダブルクリックするたびに好感度を 1 ずつ上げるつもりで書いたものです。ところが、何度ダブルクリックしても「好感度が1になった！」としか言いません。なぜでしょう。どう直せばよいでしょう。

   ```c
   OnMouseDoubleClick
   {
   	_好感度 += 1
   	"\0\s[1]好感度が%(_好感度)になった！\e"
   }
   ```

<details>
<summary>答え</summary>

`_好感度` は `_` で始まるローカル変数なので、関数が終わると消えてしまいます。次に呼ばれたときは空（0）からやり直しになるため、いつも 1 になります。`_` を取って `好感度` というグローバル変数にすれば、値が残り、終了後も保存されます。

</details>

4. 自分のランダムトークを `OnAiTalk` に 3 つ足し、そのうち 1 つは自作の関数を `%( )` で埋め込んでください。

<details>
<summary>ヒント</summary>

`ことねの好きなもの` と同じように、候補を並べた関数を作り、セリフの中に `%(関数名)` と書きます。足したら `\![raise,OnAiTalk]` で何度か試しましょう。

</details>
