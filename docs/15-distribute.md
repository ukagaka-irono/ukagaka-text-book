# 第15章 配布とネットワーク更新

## この章で学ぶこと

- 配布用ファイル nar の中身と、`install.txt` の書き方
- SSP の機能で nar を作る手順
- ネットワーク更新のしくみと、`homeurl`・`updates2.dau` の準備
- 配布先の選び方と `readme.txt` に書くこと
- ライセンスと素材の権利への配慮

いよいよ、はじめてのゴーストをほかの人に届けます。この章では、ゴーストを1つのファイルにまとめる方法と、公開後に直したものを届ける **ネットワーク更新** のしくみを学びます。

## nar ファイルとは

ゴーストは、ふつう **nar**（ナー。Nanika ARchive の略）という拡張子のファイルで配布されます。中身は zip 圧縮ファイルの拡張子を変えただけのものです。ユーザーは、この nar を起動中の SSP にドラッグ＆ドロップするだけでインストールできます。

自動でインストールされるために必要なのが **`install.txt`** です。これがないと、ユーザーは自分で解凍してフォルダを置かなければなりません。

### 配布用フォルダの構成

はじめてのゴーストなら、次のような形にまとめます。

```text
hajimete/
  install.txt              … インストールの設定（必須）
  readme.txt               … 説明書き（強く推奨）
  thumbnail.png            … ゴースト選択メニューの見本画像（省略可）
  developer_options.txt    … nar や更新ファイルに含めないものの指定（SSP・省略可）
  ghost/
    master/
      descript.txt
      （SHIORI の DLL と辞書ファイル）
  shell/
    master/
      descript.txt
      surfaces.txt
      surface0.png など
```

`install.txt` を置くのは、`ghost` と `shell` フォルダがある **いちばん上の階層** です。

### install.txt

`install.txt`

```text
charset,UTF-8
type,ghost
name,はじめてのゴースト
directory,hajimete
```

| 項目 | 意味 |
| --- | --- |
| `charset` | 文字コード。1行目に書く |
| `type` | 中身の種類。ゴーストは `ghost`、追加シェルは `shell`、バルーンは `balloon` など |
| `name` | 名前。ゴーストの `descript.txt` の `name` とそろえる |
| `directory` | インストール後のフォルダ名。半角英数字がおすすめ |

`name` と `type` は必須で、`directory` もゴーストなら必須です。`name` が `descript.txt` と食い違うと、インストール直後に新しいゴーストへ切り替える機能などがうまく働かないことがあるので、そろえておきましょう。

追加シェルだけを配るときは `type,shell` にし、`accept,ことね` のように、受け取るゴーストの \0 側の名前を書きます。

> **コラム**
> SSP では、バルーンをゴーストに同梱して一緒にインストールさせることもできます。ゴーストのフォルダの中にバルーンのフォルダ（例：`hajimete_balloon/`）を入れ、`install.txt` に `balloon.directory,hajimete_balloon` と書き足します。同梱される側の `install.txt` は不要です。

### 入れてはいけないもの

配布物には、ユーザーに不要なファイルを入れないようにします。

- SHIORI のセーブデータ（初期値として必要な場合を除く）
- `profile` フォルダ（SSP が作るもの。SSP で nar を作るときは自動で除かれます）
- 開発用ツール、テスト用の辞書、ログファイル（第14章の `ssp_SHIORI_log.txt` など）

SSP で nar を作るなら、`developer_options.txt` で除外を指定できます。

`developer_options.txt`

```text
ghost/master/ssp_SHIORI_log.txt,nonar,noupdate
ghost/master/satori_savedata.txt,nonar,noupdate
ghost/master/satori_savebackup.txt,nonar,noupdate
ghost/master/yaya_variable.cfg,nonar,noupdate
ghost/master/yaya.log,nonar,noupdate
```

`相対パス,オプション` の形で書き、`nonar` は nar に含めない、`noupdate` は更新ファイルに含めない、という意味です。フォルダを指定するときは末尾に `/` を付けます。上の例では、SSP の通信ログに加えて、里々のセーブデータ（[第9章](09-satori-practice.md)）と YAYA のセーブデータ・実行ログ（[第11章](11-yaya-practice.md)）を外しています。使わない SHIORI の行はなくてもかまいません。

## SSP で nar を作る

SSP には、フォルダをドロップするだけで nar を作る機能があります。

1. 開発中のフォルダをそのまま使わず、`hajimete` フォルダを丸ごと別の作業用の場所にコピーする。
2. コピーした側から、不要なファイルを取り除き、`install.txt` と `readme.txt` を置く。
3. 第14章の手順で「開発者用機能を有効にする」をオンにし、本体設定「開発/その他」の「フォルダをドロップした際に更新ファイルやNARを作成」もオンにする。
4. 同じページの「NAR作成位置」で、nar を出力する場所（毎回指定／フォルダと同じ／指定したフォルダ）を選ぶ。
5. 作業用の `hajimete` フォルダを、起動中のゴーストにドラッグ＆ドロップする。
6. 動作を選ぶ画面が出たら、nar の作成を選ぶ。
7. `hajimete.nar` ができる。

できた nar は、自分の SSP に一度ドロップして、正しくインストールされるか確かめましょう。手動で zip に圧縮して拡張子を `.nar` に変えても同じものになりますが、そのときは `hajimete` フォルダの「中身」を圧縮し、階層が1段深くならないように注意します。

## ネットワーク更新のしくみ

**ネットワーク更新** は、作者がサーバーに置いた新しいファイルを、ユーザーの SSP が取りにきて上書きするしくみです。ユーザーは右クリックメニューの「ネットワーク更新」（Ctrl + U）を選ぶだけで最新版になります。SSP では、ゴーストだけでなくシェルやバルーンも更新できます。

流れは次のとおりです。

1. ゴーストの `descript.txt` に、更新ファイルを置く場所（`homeurl`）を書いておく。
2. SSP がその場所にある **`updates2.dau`**（ファイルの一覧とチェック用の値が書かれた更新ファイル）を読み、手元のファイルと比べる。
3. 違うファイルだけをダウンロードして上書きする。

### 準備1：サーバーと homeurl

まず、ファイルを置けるサーバー（個人の Web サイト用のレンタルサーバーなど）を用意します。無料サービスの中には、見慣れない拡張子を受け付けなかったり、テキストファイルに広告を入れたりするものがあるので注意してください。

次に、ゴーストの `descript.txt` に URL を書きます。

`ghost/master/descript.txt`（追記）

```text
homeurl,https://example.com/ukagaka/hajimete/
```

`example.com/ukagaka/hajimete/` の部分は、実際にファイルを置く場所に変えます。**URL の最後の `/` を忘れないでください**。この行は、最初に配る nar にも入れておく必要があります。入っていないと、最初の利用者は更新を受け取れません。

> **コラム**
> SHIORI からも `homeurl` を返せます。ゴースト起動中は SHIORI 側の値が優先されます。

### 準備2：updates2.dau を作る

1. 更新に含めたいファイルがそろった作業用の `hajimete` フォルダを、起動中のゴーストにドラッグ＆ドロップする。
2. 動作を選ぶ画面で、更新ファイルの作成を選ぶ。
3. フォルダのいちばん上に `updates2.dau` ができる。

SSP では、`install.txt` を置いた状態でドロップし、`updates2.dau` と nar をまとめて作ることもできます。最初の nar に `updates2.dau` を入れておくと、ユーザーの初回の更新が軽くなります。

### 準備3：アップロードする

作業用フォルダの中身（`ghost`、`shell`、`updates2.dau`、`readme.txt` など）を、`homeurl` の場所にそのままの構成でアップロードします。

- FTP ソフトを使うなら、必ず **すべてバイナリモード** で送ります。アスキーモードだとファイルが変わってしまい、更新に失敗します。
- サーバーが `.dau` という拡張子を受け付けないときは、代わりに `updates.txt` を使えます。

### 2回目からの更新

直すたびに、次をくり返します。

1. ファイルを直す。
2. `updates2.dau` を作り直す。
3. 変わったファイルと `updates2.dau` をアップロードする。

> **注意**
> `updates2.dau` を作ったあとにファイルを1文字でも変えると、中身が合わなくなり「MD5不一致」のエラーになります。最後に必ず作り直してからアップロードしましょう。

更新は「上書き」なので、サーバーからファイルを消しても、ユーザーの手元のファイルは消えません。不要になったファイルを消したいときは、いちばん上の階層に `delete.txt` を置き、`ghost\master\old.txt` のように、消したいファイルを `\` 区切りで1行ずつ書きます。

### 更新を試す

- 古い版のゴーストを手元に残しておき、アップロード後に実際にネットワーク更新して、正常に終わるか確かめます。
- 開発中のゴーストでは、開発用パレットの「自動更新無効」や「更新チェックのみ」を使うと、作業中のファイルを上書きする事故を防げます（第14章）。

なお、nar 作成から更新ファイル作成・アップロードまでを一括で行う支援ツールとして「ゴースト配布系自動化システム（GDM）」もあります。UKADOC の [配布用ファイルの作成](https://ukatech.shillest.net/ukadoc-spec/dev/nar/) から案内をたどれます。

## 配布先と readme

### どこで配るか

SSP ヘルプでは、次のような方法が挙げられています。

- **ネットワーク更新をしないなら**：nar をオンラインストレージやアップローダーに置くだけでも公開できます。
- **ネットワーク更新をするなら**：前の節で用意したサーバーに、nar も一緒に置くのが分かりやすいでしょう。

公開したら、SSP ヘルプの「リンク集」に載っているゴーストの紹介・データベースサイトなどで知らせると、見つけてもらいやすくなります。

### readme.txt に書くこと

ゴーストのいちばん上の階層に置いた `readme.txt` は、インストール時や右クリックメニューから読めます。最低限、次のことを書きましょう。

`readme.txt`

```text
charset,UTF-8
はじめてのゴースト
作者：あなたの名前
連絡先：（メールアドレスや Web サイト）
配布元：（nar を置いた場所）

■ これは何？
ことねと、相棒の小鳥ぴーすけが、デスクトップでおしゃべりするゴーストです。

■ 動作環境
SSP

■ 使っているもの
SHIORI：（里々 または YAYA。配布元と作者）
シェル・素材：（自作 / 借りた素材の名前・作者・配布元）

■ 利用条件
（改変や再配布をしてよいかなど）

■ 更新履歴
（日付） 公開
```

SSP では、`readme.txt` の代わりに Markdown 形式の `readme.md` も使えます。インストール前に必ず同意してほしい条件があるときは `terms.txt` も置けますが、インストールを止めて表示するので、本当に必要なときだけにしましょう。

## ライセンスと素材の権利

最後に、とても大事な話です。ゴーストには、自分以外の人が作ったものがたくさん入っています。

- **SHIORI**：里々や YAYA の DLL を同梱するときは、それぞれの配布元が示す条件（ライセンス表記の同梱など）に従います。
- **フリーシェル・バルーン・画像・音・フォント**：配布元の利用条件を必ず読み、クレジットの書き方、改変・再配布の可否を守ります。条件がはっきりしないものは、作者に確認できるまで使わないのが安全です。
- **ほかの作品のキャラクター**：作者や権利者の許可なく使うことはできません。

そして、あなたのゴーストをほかの人がどう使ってよいか（改変してよいか、素材として使ってよいか、など）も、`readme.txt` に書いておきましょう。書いてあれば、ユーザーも安心して楽しめます。

## まとめ

- ゴーストは nar（中身は zip）で配る。いちばん上の階層に `install.txt` を置く。
- `install.txt` には `type`・`name`・`directory` を書く。`name` は `descript.txt` とそろえる。
- SSP では、開発者向けの設定をオンにしてフォルダをゴーストにドロップすると、nar や `updates2.dau` を作れる。
- ネットワーク更新は、`homeurl` の場所にある `updates2.dau` と手元を比べて上書きするしくみ。URL の最後の `/` を忘れない。
- `updates2.dau` を作ったら、それ以降ファイルを変えずにバイナリモードでアップロードする。
- `readme.txt` に作者・連絡先・使った素材・利用条件を書き、借りたものの条件を守る。

## 練習問題

1. 作った nar を SSP にドロップしても、自動でインストールされません。何を確かめればよいでしょう。
2. 更新をアップロードしたのに、ユーザーから「MD5不一致のエラーが出る」と言われました。考えられる原因を2つ挙げてください。
3. 前の版で配った `ghost/master/test.txt` を、ネットワーク更新でユーザーの手元から消したいです。どうすればよいでしょう。

<details>
<summary>答えとヒント</summary>

1. いちばん上の階層に `install.txt` があるか、`type`・`name`・`directory` が書かれているか、圧縮したときに階層が1段深くなっていないかを確かめます。
2. 「`updates2.dau` を作ったあとでファイルを書き換えた」「FTP をアスキーモードで送った」などです。サーバーがファイルを書き換えている（広告の挿入など）こともあります。
3. いちばん上の階層に `delete.txt` を置き、`ghost\master\test.txt` と書きます。`updates2.dau` を作り直してから、`delete.txt` と `updates2.dau` をアップロードします。

</details>
