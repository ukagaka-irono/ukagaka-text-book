# 第9章 里々実践

## この章で学ぶこと

- 起動・初回起動・終了・時報などのイベントを、里々で書く方法
- つつかれ・なでられへの反応と、メニュー（選択肢）の作り方
- 変数の保存と、条件で話す内容を変える方法（採用条件式・`＞`・`when`）
- 入力ボックスでユーザーの言葉を受け取る方法と、トーク間隔の変え方
- 里々でよくあるつまずきと、その直し方

## この章で作るもの

[第8章](08-satori-basics.md) では、ランダムトークを話すだけのゴーストを作りました。この章では、ゴーストがユーザーの操作や時間に反応するようにしていきます。辞書は内容ごとに、次の 3 つのファイルを追加します。

| ファイル | 中身 |
| --- | --- |
| `dic_boot.txt` | 起動・初回起動・終了・時報 |
| `dic_mouse.txt` | つつかれ・なでられ |
| `dic_menu.txt` | メニュー・呼び名の変更・話しかけ・トーク間隔 |

完成形は [`samples/satori/hajimete/`](../samples/satori/hajimete/) にあります。

> **注意**
> この章のコードには、見えない **タブ文字** が入っている行があります（`＊名前` や `＠名前` のあとに条件を書く行、`＞名前` のあとに条件を書く行、`＿ラベル` のあとに ID を書く行、`＄名前` のあとに値を書く行）。ここは半角スペースでは働きません。コピーしたあとにエディタでタブがスペースに変わっていないか確かめてください。迷ったら、サンプルのファイルをそのまま使うのが確実です。

## イベントの書き方

### イベント名と同じ名前の文を書く

里々でイベントに答えるのは、とても簡単です。**イベント名と同じ名前の文** を書けば、そのイベントが届いたときに里々が実行してくれます。第8章の `＊OnBoot` がまさにそれでした。イベントに付いてくる情報（Reference、[第7章](07-shiori-events.md) を参照）は、`（Ｒ０）` `（Ｒ１）` … で取り出せます。

文がないイベントには、里々は何も返しません。ただし、いくつかのイベントには里々が用意した **デフォルトの動作** があり、文を書かなくても動きます（マウスの反応など。あとで説明します）。

### 起動・初回起動・終了

起動まわりで使うのは、主に次の 3 つです。

| イベント | 届くとき | 里々での補足 |
| --- | --- | --- |
| `OnFirstBoot` | インストール後、はじめて起動したとき | `＊OnFirstBoot` がなければ `＊OnBoot` が使われる |
| `OnBoot` | ふだんの起動 | 古い書き方の `＊起動` も使える |
| `OnClose` | 終了するとき | 返事の最後に、終了の命令 `\-` を里々が付ける |

`OnClose` のトークには、ゴーストを終了させるさくらスクリプト `\-` を自分で書く必要はありません。里々が付けてくれます。`＊OnClose` を書かなかった場合も、里々は `\-` だけを返して、ゴーストを終了させます。

`ghost/master/dic_boot.txt`（起動・終了の部分）

```text
＃ ---- はじめての起動 ----
＊OnFirstBoot
：（5）はじめまして！　わたし、ことね。
：オレはぴーすけ。ことねの相棒だぴ。
：これからよろしくね、（呼び名）。
：ダブルクリックしてくれたら、メニューを出すぴ。

＃ ---- 2回目からの起動 ----
＊OnBoot
：（時間のあいさつ）、（呼び名）！
：（when、（起動回数）>=10、もうすっかり常連さんだぴ。、今日もよろしくだぴ。）

＊OnBoot
：あ、（呼び名）。（時間のあいさつ）！
：これで（起動回数）回目の起動だぴ。

＃ ---- 終了 ----
＊OnClose
：今日はおしまい？　またね、（呼び名）。
：おやすみだぴ。

＊OnClose
：おつかれさま、（呼び名）。
：また呼んでほしいぴ。
```

`（呼び名）` は、ユーザーの呼び方を入れておく変数です。`（時間のあいさつ）` は時間帯で変わる単語群、`（起動回数）` は里々が数えてくれる起動の回数です。どれもこのあと説明します。

### 時間帯で言葉を変える（採用条件式）

`＊名前` や `＠名前` のあとに **タブ文字** で区切って式を書くと、その式が成り立つ（0 以外になる）ときだけ、そのまとまりが選ばれる候補になります。これを **採用条件式** といいます。時間帯であいさつを変えてみましょう。

`ghost/master/dic_boot.txt`（あいさつの部分）

```text
＠時間のあいさつ	(（現在時）>=5)&&(（現在時）<11)
おはよう
＠時間のあいさつ	(（現在時）>=11)&&(（現在時）<18)
こんにちは
＠時間のあいさつ	(（現在時）>=18)||(（現在時）<5)
こんばんは
```

- `（現在時）` は、いまの時（0〜23）です。
- 式の中では、計算の順番を決めるカッコに **半角** の `(` `)` を使います。全角の `（）` は里々の呼び出しになってしまうためです。
- `&&` は「かつ」、`||` は「または」です。比較には `<` `>` `<=` `>=` `==` `!=` が使えます。

条件のないまとまりは、いつでも候補になります。上のように、すべての候補に重ならない条件を付けておくと、時間帯ごとにきっちり切り替わります。

> **コラム**
> 時間で変わるトークを確かめるのに、時計が進むのを待つ必要はありません。SSP の開発用パレットには「現在時刻の仮想的変更」があり、SSP が認識する時刻だけを好きな日時にできます（[第14章](14-debug.md)）。

## マウスに反応する

### つつかれ・なでられ

里々には、マウスの操作に反応するためのデフォルトの動作があります。文の名前を「キャラクターの番号」＋「当たり判定の名前」＋「反応の種類」にしておくと、里々がそれを呼び出します。

| 操作 | 呼ばれる文の名前（例） |
| --- | --- |
| ダブルクリック（つつく） | `＊0Headつつかれ` |
| 同じ場所の上でマウスを動かし続ける（なでる） | `＊0Headなでられ` |
| 同じ場所でホイールを回す | `＊0Headころころ` |

- 先頭の数字はキャラクターの番号で、ことね（\0 側）が `0`、ぴーすけ（\1 側）が `1` です（`OnMouseDoubleClick` などの Reference3）。
- `Head` の部分は **当たり判定** の名前です（Reference4）。当たり判定は、シェルの `surfaces.txt` で「この範囲は Head」のように決めます（[第12章](12-shell.md)）。大文字・小文字も含めて、シェルに書いた名前と完全に同じにしてください。
- なでられは、同じ場所の上で `OnMouseMove` が一定回数（既定は 60 回）届いたときに呼ばれます。回数は `＄なでられ反応回数` で変えられます。また、ゴーストが話している最中は反応しません。

`ghost/master/dic_mouse.txt`（反応の部分）

```text
＊0Headつつかれ
：（2）あいたっ。頭はつつかないでよー。
：いい音がしたぴ。

＊0Faceつつかれ
：（1）ほっぺた、つつかないでー。
：ことねのほっぺは、よくのびるぴ。

＊1Headつつかれ
（11）ぴっ！？　オレの頭はつつくものじゃないぴ！
：ぴーすけ、大丈夫？

＃ ---- なでる（同じ場所の上でマウスを動かし続ける） ----
＊0Headなでられ
＄なでられた回数＝（なでられた回数）+1
：（1）えへへ……。
：これで（なでられた回数）回なでてもらったぴ。

＊1Headなでられ
（11）ぴぃ……気持ちいいぴ……。
：ぴーすけ、とろけてる。
```

`＊1Headつつかれ` と `＊1Headなでられ` は、ぴーすけから話し始めるので、最初の行に `：` を付けていません（第8章）。

### 反応を書いていない場所ではメニューを開く

デフォルトの動作では、反応を書いていない場所をつついても、何も起きません。そこで、「反応を書いた場所ならその反応、それ以外ならメニュー」となるように、`＊OnMouseDoubleClick` を自分で書きます。イベント名の文を書くと、里々のデフォルトの動作よりそちらが優先されるので、つつかれの呼び出しも自分で書きます。

`ghost/master/dic_mouse.txt`（ダブルクリックの部分）

```text
＊OnMouseDoubleClick
＞（Ｒ３）（Ｒ４）つつかれ	（文「（Ｒ３）（Ｒ４）つつかれ」の存在）
＞メニュー
```

ここで新しく使っているのが **ジャンプ** の `＞` です。

- `＞名前` は、その名前の文へ移ります。移った先から戻ってくることはありません。
- `＞名前` のあとにタブで区切って式を書くと、その式が成り立つときだけ移ります。成り立たないときは、次の行に進みます。
- `（文「名前」の存在）` は、その名前の文があれば 1、なければ 0 になる、里々が用意している名前です。

`（）` は内側から展開されるので、ことねの頭をつついたときは `（Ｒ３）（Ｒ４）つつかれ` が `0Headつつかれ` になり、その文があれば移ります。なければ次の行の `＞メニュー` へ進みます。メニューの中身は、このあとの「選択肢とメニュー」で作ります。

## 時報

SSP では、毎正時（何時ちょうど）に `OnHourTimeSignal` というイベントが届きます。ゴーストが話せない状態のときは、話せるようになるまで待ってから届くので、少し遅れることがあります。採用条件式と組み合わせて、時刻ごとに言葉を変えてみましょう。

`ghost/master/dic_boot.txt`（時報の部分）

```text
＊OnHourTimeSignal	（現在時）==12
：（2）お昼の12時だよ。
：ごはんの時間だぴ！

＊OnHourTimeSignal	(（現在時）>=22)||(（現在時）<5)
：もう（現在時）時だよ。
：夜ふかしはほどほどにするぴ。

＊OnHourTimeSignal	(（現在時）!=12)&&(（現在時）>=5)&&(（現在時）<22)
：（現在時）時になったよ。
：時間がたつのは早いぴ。
```

`OnHourTimeSignal` は SSP 独自のイベントです。ほかのベースウェアでも動かしたいときは、[付録B](appendix-b-events.md) で別のイベントを探してください。

## 選択肢とメニュー

### ＿ で選択肢を作る

行頭に全角のアンダーバー `＿` を書くと、その行が **選択肢** になります。里々はこれをさくらスクリプトの `\q[ラベル,ID]`（[第6章](06-sakura-script.md)）に変換します。

| 書き方 | 意味 |
| --- | --- |
| `＿ラベル` | 表示する文字（ラベル）と ID を同じにする |
| `＿ラベル`＋タブ＋`ID` | ラベルと ID を別にする |

ユーザーが選択肢を選ぶと、ベースウェアから `OnChoiceSelect` が届きます。里々は、`＊OnChoiceSelect` を書いていなければ、**ID と同じ名前の文** を実行します。つまり、選択肢の ID と同じ名前で文を書いておけば、それが選んだあとの続きになります。

`ghost/master/dic_menu.txt`（メニューの部分）

```text
＊メニュー
：なにかご用？
＿なにか話して
＿話しかける
＿呼び名を変える
＿トークの間隔を変える
＿なんでもない

＊なにか話して
＞

＊なんでもない
：（5）はーい。またあとでね。
```

`＿なにか話して` を選ぶと、`＊なにか話して` が実行されます。名前のない `＞` は、ランダムトーク（名前のない文）へ移るという意味です。ほかの選択肢の続きは、このあとの節で書いていきます。

選択肢の ID を `On` で始めると、ベースウェアが ID をイベント名として扱うため、`OnChoiceSelect` を経由しません。メニューの ID は、日本語の名前にしておくのが無難です。

## 変数を保存する

里々の変数は、ゴーストの終了時に `ghost/master/satori_savedata.txt` へ **自動で保存** され、次に起動したときに元に戻ります。保存のために特別なことを書く必要はありません。

`＊0Headなでられ` で使った `＄なでられた回数＝（なでられた回数）+1` は、なでられるたびに 1 ずつ増え、ゴーストを終了しても次回に引き継がれます。まだない変数は、計算の中では 0 として扱われるので、最初の 1 回目から正しく数えられます。

`（起動回数）` は、里々が自分で用意している変数です。起動するたびに 1 増えるので、そのまま使えます。

### はじめに値を入れておく

ユーザーの呼び方を変数 `呼び名` に入れておき、あとからメニューで変えられるようにします。まだ一度も設定していないときは「ユーザーさん」にしたいので、辞書の読み込みが終わった直後に里々が実行する `＊OnSatoriLoad` で、値がなければ入れるようにします。

`ghost/master/dic_boot.txt`（読み込み直後の部分）

```text
＃ ---- 辞書を読み込んだ直後（結果は使われない） ----
＊OnSatoriLoad
＞呼び名の初期設定	（変数「呼び名」の存在）==0

＊呼び名の初期設定
＄呼び名	ユーザーさん
```

- `（変数「呼び名」の存在）` は、変数があれば 1、なければ 0 です。
- `＄呼び名` のあとはタブ文字です。タブで区切ると、右側を計算せずにそのまま代入します。文字列を入れるときはこちらを使い、数を計算して入れるときは `＝` を使います。

`＊OnSatoriLoad` は、セーブデータを読み込んだあとに実行されます。そのため、一度呼び名を変えたあとは、保存された呼び名がそのまま使われます。

## 条件で話す内容を変える

ここまでに、条件で分ける方法が 3 つ出てきました。使い分けをまとめておきます。

| 方法 | 書き方 | 向いている場面 |
| --- | --- | --- |
| 採用条件式 | `＊名前`＋タブ＋式、`＠名前`＋タブ＋式 | 文や単語群をまるごと条件で選ぶ |
| 条件つきジャンプ | `＞名前`＋タブ＋式 | 途中から別の文に移る |
| `when` | `（when、式、成り立つとき、成り立たないとき）` | セリフの一部だけを変える |

`when` は、`＊OnBoot` の次の行で使っています。

```text
：（when、（起動回数）>=10、もうすっかり常連さんだぴ。、今日もよろしくだぴ。）
```

起動回数が 10 以上ならひとつめ、そうでなければふたつめのセリフになります。引数の区切りは全角の読点 `、` なので、セリフの中に `、` を入れないように注意してください。

里々に同梱されている関数集 **ssu** にも、同じ形の `（if、式、成り立つとき、成り立たないとき）` があります。ただし `if` は、どちらを選ぶかに関係なく、両方の引数の中の `（）` を先に実行してしまいます。両方に変数の代入などが入っていると、選ばれなかったほうも実行されるので、里々の内蔵関数の `when` を使うほうが安全です。

## 話しかけと入力ボックス

ユーザーに文字を入力してもらうには、さくらスクリプトの `\![open,inputbox,ID,表示時間]` で **入力ボックス** を開きます。表示時間はミリ秒で、0 にすると時間切れなしになります。

入力が決定されると、ふつうは `OnUserInput` が届きます。SSP では、**ID を `On` で始めておくと、その ID と同じ名前のイベントが届き、Reference0 に入力した文字が入ります**。これを使うと、入力ごとに受け取る文を分けられて便利です。

`ghost/master/dic_menu.txt`（呼び名を変える部分）

```text
＊呼び名を変える
：なんて呼べばいいかな？
\![open,inputbox,OnHajimeteNameInput,0]

＊OnHajimeteNameInput
＄呼び名	（Ｒ０）
＞呼び名を元に戻す	（変数「呼び名」の存在）==0
：わかった！　これからは「（呼び名）」って呼ぶね。
：よろしくだぴ、（呼び名）。

＊呼び名を元に戻す
＄呼び名	ユーザーさん
：何も書いてなかったから、「ユーザーさん」のままにしておくね。
```

空のまま決定されると、`＄呼び名`（タブ）`（Ｒ０）` は空の値の代入になり、変数が消えてしまいます。そこで、消えていたら `＊呼び名を元に戻す` へ移って、元に戻しています。

同じしくみで、ユーザーが話しかけられるようにもします。

`ghost/master/dic_menu.txt`（話しかける部分）

```text
＊話しかける
：なあに？　なんでも話してね。
\![open,inputbox,OnHajimeteTalkInput,0]

＊OnHajimeteTalkInput
：「（Ｒ０）」かあ。（あいづち）
：ことね、ちゃんとわかってるぴ？

＠あいづち
なるほどね。
そうなんだ！
ふむふむ。
```

入力された言葉の中身によって返事を変える方法（キーワードで文を探す「コミュニケート」のしくみなど）もありますが、本書では扱いません。里々の説明書の「コミュニケート」を参照してください。

## トーク間隔の設定

ランダムトークの間隔は、システム変数 `＄喋り間隔`（秒）で決まります。第8章では `satori_conf.txt` の `＊初期化` で設定しましたが、トークの中で代入すれば、その場で変えられます。メニューから選べるようにしてみましょう。

`ghost/master/dic_menu.txt`（トーク間隔の部分）

```text
＊トークの間隔を変える
：どのくらいおしゃべりしようか？
＿1分ごとに話す	間隔1分
＿2分ごとに話す	間隔2分
＿5分ごとに話す	間隔5分
＿しばらく静かにする	間隔なし

＊間隔1分
＄喋り間隔＝60
：（5）わかった、たくさん話すね！

＊間隔2分
＄喋り間隔＝120
：いつもくらいのペースにするね。

＊間隔5分
＄喋り間隔＝300
：ちょっとひかえめにするね。

＊間隔なし
＄喋り間隔＝0
：しばらく静かにしてるね。
：用があったらダブルクリックするぴ。
```

- `＄喋り間隔` を 0（または 3 未満）にすると、ランダムトークをしなくなります。
- 実際の間隔は、`＄喋り間隔誤差`（％、既定は 10）の分だけばらつきます。
- システム変数に代入した値も、ふつうの変数と同じようにセーブデータに保存されます。そのため、メニューで選んだ間隔は次回の起動でも続きます。

ここまでで、サンプルの辞書がすべてそろいました。ゴーストを読み込み直して、起動・つつく・なでる・メニュー・入力ボックス・時報（SSP の仮想時刻を使うと便利です）を、ひとつずつ試してみてください。

## よくあるつまずき

| 症状 | 原因と対処 |
| --- | --- |
| まったく反応しない・文字がそのまま出る | `＊` `＠` `＄` `：` `（）` `＿` `＞` が半角になっていないか確かめる。里々の記号は全角。 |
| 条件や選択肢の ID が効かない | 区切りがタブ文字ではなく、半角スペースになっている。エディタの「タブをスペースに変換」設定も確かめる。 |
| ランダムトークをしない | `＄喋り間隔` が設定されていない（既定は 0）か、3 未満になっている。 |
| つついても反応しない | 文の名前の当たり判定名が、シェルの `surfaces.txt` と一字一句同じか確かめる（`Head` と `head` は別）。SSP の開発用パレットの「当たり判定を表示」で名前を確認できる。 |
| セリフの途中で話し手が入れ替わる | セリフの中に全角の `：` がある。文字として出すときは `φ：` と書く。 |
| `（名前）` がそのまま表示される | 単語群・文・変数の名前の打ち間違いか、まだ値を入れていない変数を表示している。 |
| 辞書が読み込まれない・エラーになる | `（` を閉じ忘れている。辞書の終わりまで `）` が閉じていないとエラーになる。 |
| `satori_conf.txt` の `＄喋り間隔` を変えたのに反映されない | 里々は `＊初期化` のあとでセーブデータを読み込むので、前回保存された値で上書きされる。ゴーストを終了してから `satori_savedata.txt` と `satori_savebackup.txt` を削除する（ほかの変数も消えるので注意）。 |
| 文字化けする | ACP 版の `satori.dll` に UTF-8 の辞書を読ませている。Unicode 版の `satori.dll` を使うか、辞書を Shift_JIS で保存し直す。 |

辞書の書き間違いは、ログを受け取るツール（tama など）でエラーとして確認できます。くわしいデバッグの方法は [第14章 テストとデバッグ](14-debug.md) で説明します。

## まとめ

- イベントに答えるには、イベント名と同じ名前の文を書く。Reference は `（Ｒ０）` `（Ｒ１）` … で取り出す。
- `＊OnFirstBoot` がなければ `＊OnBoot` が使われる。`＊OnClose` の最後の `\-` は里々が付ける。
- `＊0Headつつかれ` `＊0Headなでられ` のように名前を付けると、マウスの操作に反応できる。当たり判定名はシェルに合わせる。
- 行頭の `＿` で選択肢を作り、ID と同じ名前の文で続きを書く。
- 変数は終了時に自動で保存される。最初の値は `＊OnSatoriLoad` で入れておける。
- 条件で分けるには、採用条件式・条件つきの `＞`・`when` を使い分ける。条件や ID の区切りはタブ文字。
- 入力ボックスは `\![open,inputbox,ID,表示時間]`。SSP では ID を `On` で始めると、その名前のイベントで入力を受け取れる。
- `＄喋り間隔` をトークの中で代入すれば、ランダムトークの間隔をその場で変えられる。

## 練習問題

1. ことねの体（当たり判定名を `Bust` とします）をつついたときの反応を書いてください。

   <details>
   <summary>答えの例</summary>

   ```text
   ＊0Bustつつかれ
   ：（2）ちょ、ちょっと！
   ：ことねが驚いてるぴ。
   ```

   `＊OnMouseDoubleClick` は `（文「0Bustつつかれ」の存在）` が 1 になるので、この文へ移るようになります。

   </details>

2. メニューに「おやつの話をして」という選択肢を追加し、選ぶとおやつの話をするようにしてください。単語群 `＠おやつ`（第8章）を使ってかまいません。

   <details>
   <summary>答えの例</summary>

   `＊メニュー` に `＿おやつの話をして` の 1 行を足し、同じ名前の文を書きます。

   ```text
   ＊おやつの話をして
   ：今日のおやつは（おやつ）にしようかな。
   ：オレにも分けてほしいぴ。
   ```

   </details>

3. 起動回数が 1 回目のときだけ、`＊OnBoot` の代わりに特別なあいさつをさせたいとします。採用条件式を使って書いてください（`OnFirstBoot` を使わない方法で）。

   <details>
   <summary>ヒント</summary>

   `＊OnBoot` のあとにタブ文字を入れて、`（起動回数）==1` のような式を書きます。条件のない `＊OnBoot` はいつでも候補になるので、ほかの `＊OnBoot` にも `（起動回数）!=1` のような条件を付けておくと、きっちり分かれます。

   </details>

里々を選んだ人は、第4部（YAYA）を飛ばして [第12章 シェルを作る](12-shell.md) に進んでかまいません。
