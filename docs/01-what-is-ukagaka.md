# 第1章 伺かとは

## この章で学ぶこと

- 「伺か」がどんなソフトウェアで、どんな遊び方をするものなのか
- ベースウェア・ゴースト・シェル・バルーン・SHIORI などの部品が、どうつながっているか
- \0 側と \1 側の「二人組」で会話する、伺かの伝統
- この本で使うベースウェア SSP の位置づけ
- この本で作るサンプルゴースト「はじめてのゴースト」の紹介

## デスクトップに住むキャラクター

**伺か**（うかがか）は、パソコンのデスクトップにキャラクターを表示して、おしゃべりさせたり、マウスで触って反応を楽しんだりするソフトウェアです。こうした種類のソフトは **デスクトップマスコット** と呼ばれます。

伺かのキャラクターは、ただ立っているだけではありません。

- 放っておくと、ときどき自分から話しかけてきます。
- 頭のあたりでマウスを動かすと「なでられた」と反応したり、ダブルクリックするとメニューを出したりします。
- 時刻やパソコンの状態、ユーザーの操作など、さまざまな「出来事」に合わせて話す内容が変わります。

何がどこまでできるかは、キャラクターごとにまったく違います。雑談をするだけのもの、ミニゲームを遊べるもの、時計やメモ帳の代わりになるものなど、作者の数だけ個性があります。この「キャラクターデータ」のことを **ゴースト** と呼び、たくさんのゴーストがインターネット上で無料で配布されています。

> **コラム：「伺か」という名前**
> 伺かは、もともと「何か。」という名前で公開されたソフトがはじまりで、のちに「伺か」と呼ばれるようになりました。その本家のソフトは **MATERIA**（マテリア）とも呼ばれます。現在では「伺か」という言葉は、本家ソフトだけでなく、ゴーストを中心とした創作ジャンルやコミュニティ全体を指す、ゆるやかな呼び名になっています。

## 伺かを形づくる部品

伺かの面白いところは、キャラクターが一つのプログラムではなく、**役割ごとに分かれた部品の組み合わせ** でできていることです。部品ごとに作者が違うことも珍しくありません。

### 部品の一覧

| 部品 | ひとことで言うと | 役割 |
| --- | --- | --- |
| **ベースウェア** | 舞台 | ゴーストを動かす土台のソフト。画面表示やマウス操作の受け付け、部品同士の橋渡しをする。SSP など |
| **ゴースト** | 心 | キャラクターの人格。何を話し、どう反応するかを決める部分。シェルとセットで配布されることが多い |
| **シェル** | 体 | キャラクターの見た目（立ち絵の画像）。表情ごとの画像や、触れる場所の設定を含む |
| **バルーン** | 吹き出し | セリフを表示する小さなウィンドウ。全ゴーストで共有して付け替えられる |
| **SHIORI** | 頭脳 | ゴーストの中で、出来事に応じたセリフを組み立てるプログラム。里々や YAYA などがある |
| **SAORI** | 道具 | SHIORI の機能を広げる追加モジュール。計算やファイル操作など、SHIORI 単体でできないことを補う |
| **MAKOTO** | 口調フィルタ | セリフの中の言葉を置き換える仕組み。語尾を変えて口調を変える演出などに使う |
| **プラグイン** | 便利機能 | ベースウェア全体に機能を追加する部品。どのゴーストを表示していても使える |
| **ヘッドライン** | ニュース係 | Web サイトの更新情報を取ってきて、ゴーストに読み上げさせる仕組み |

### 部品のつながり

フォルダの入れ物として見ると、次のような関係になっています（SSP の場合）。

```text
SSP（ベースウェア）
├─ ゴースト「はじめてのゴースト」
│   ├─ ghost/master/ … 心の部分
│   │   ├─ SHIORI（里々や YAYA）と、セリフを書いた辞書
│   │   ├─ SAORI（必要なときだけ）
│   │   └─ MAKOTO（必要なときだけ）
│   └─ shell/master/ … 体の部分（シェル）
│       ├─ 表情ごとの画像
│       └─ surfaces.txt（触れる場所などの設定）
├─ バルーン（吹き出し。全ゴーストで共有）
├─ プラグイン（SSP 全体の追加機能）
└─ ヘッドライン（Web の更新情報を取ってくる部品）
```

シェルはゴーストの中に入っていて、一つのゴーストが複数のシェルを持つこともできます。シェルを切り替えると、キャラクターが「着替えた」ように見えます。一方、バルーンは特定のゴーストの持ち物ではなく、ベースウェアに置かれて全ゴーストから使われます。

### キャラクターが話すまでの流れ

ゴーストが一言しゃべるまでには、部品の間で次のようなやりとりが起きています。

```text
1. 出来事が起きる        例：起動した、頭をなでられた、1秒たった
        ↓
2. ベースウェア → SHIORI  「OnBoot が起きました」と知らせる（イベント）
        ↓
3. SHIORI が辞書を調べて、返事のセリフを組み立てる
        ↓
4. SHIORI → ベースウェア  さくらスクリプトで書かれたセリフを返す
        ↓
5. ベースウェアが表情を変え、バルーンに文字を表示する
```

ここに出てくる **イベント** は、ベースウェアが SHIORI に知らせる「出来事」のことで、`OnBoot`（起動した）のような名前がついています。**さくらスクリプト** は、セリフの中に「ここで表情を変える」「ここで相方に話者を交代する」といった指示を埋め込むための書き方です。どちらも、この本の第2部で詳しく学びます。

この仕組みのおかげで、ゴーストの作者は「どんな出来事に、どう返事をするか」を書くことに集中できます。画面への表示やマウスの処理は、ベースウェアがまとめて引き受けてくれるのです。

## 二人組の伝統 ― \0 側と \1 側

伺かのゴーストの多くは、**二人組** で登場します。メインのキャラクターと、その相方です。ゴーストを眺めていると、二人が漫才のように掛け合いをしているのがわかるでしょう。

- **\0 側（メインキャラクター）**：主役のキャラクター。「本体」とも呼ばれます。
- **\1 側（サブキャラクター）**：相方のキャラクター。「相方」とも呼ばれます。

`\0` や `\1` は、さくらスクリプトで「ここから先はこのキャラクターが話す」と切り替えるときに使う記号です。そこから、それぞれのキャラクターをこう呼ぶようになりました。

昔からのユーザーは、\0 側を **さくら側**、\1 側を **うにゅう側** と呼ぶこともあります。これは、本家の伺かに最初から入っていたゴーストで、メインキャラクターの名前が「さくら」、相方の名前が「うにゅう」だったことの名残です。古い資料ではほかに「けろ側」という呼び方も見かけます。

もちろん二人組は決まりではありません。一人だけのゴーストも、三人以上のゴーストもあります。SSP に最初から入っているゴースト「Emily/Phase4.5」は三人のキャラクターが掛け合いをします。それでも「ボケとツッコミの二人組」は、伺からしさを感じさせる定番のスタイルです。

## ベースウェア SSP

ゴーストを動かすには、ベースウェアが必要です。本家の MATERIA のほかにも、互換性を持つベースウェアがいくつか作られてきました（CROW、ninix-kagari など）。

その中で、現在もっとも広く使われ、開発が続いているのが **SSP** です。SSP には次のような特徴があります。

- 多くの既存ゴーストと高い互換性があり、軽く動きます。
- 複数のゴーストを同時にデスクトップに立たせられます。
- ネットワーク更新、プラグイン、ヘッドライン、カレンダーなど、便利な機能が豊富です。
- ゴーストを作る人のための開発者用機能（エラーの表示、当たり判定の確認、配布ファイルの作成など）がそろっています。

この本では、遊ぶときも作るときも SSP を使います。この本で「SSP では」と書いてある機能は、ほかのベースウェアでは使えないことがあると考えてください。

> **コラム：SSP は何の略？**
> SSP はもともと「Sakura Script Player」の略でしたが、現在は特に何の略でもない、ということになっています。

## この本で作るもの

この本では、一冊を通して一つのゴーストを育てていきます。名前は **「はじめてのゴースト」** です。

| 項目 | 内容 |
| --- | --- |
| ゴースト名 | はじめてのゴースト |
| フォルダ名 | `hajimete` |
| \0 側 | **ことね**（明るい女の子。一人称は「わたし」） |
| \1 側 | **ぴーすけ**（ことねの相棒の小鳥。一人称は「オレ」、語尾は「〜ぴ」） |
| ユーザーの呼び方 | 「ユーザーさん」 |

完成すると、たとえば起動したときにこんな会話をするゴーストになります。

```text
ことね：おはよう、ユーザーさん！ 今日もよろしくね。
ぴーすけ：オレもいるぴ。忘れないでほしいぴ。
```

制作の流れは次のとおりです。

1. 第2〜3章で SSP を入れて、いろいろなゴーストで遊んでみます。
2. 第4〜7章で、ゴーストのフォルダ構成、`descript.txt`、さくらスクリプト、SHIORI とイベントの仕組みを学びます。
3. 第8〜11章で、会話を書く SHIORI として **里々** か **YAYA** のどちらかを選んで、ことねとぴーすけのセリフを書きます。
4. 第12〜13章でシェルとバルーンの仕組みを学び、見た目を整えます。
5. 第14〜15章でテストとデバッグをして、nar ファイルにまとめて配布し、ネットワーク更新に対応させます。

完成形の辞書は、この本のリポジトリの `samples/` フォルダに置いてあります。シェルの画像は同梱していないので、用意のしかたは第12章で説明します。

## まとめ

- 伺かは、デスクトップにキャラクターを住まわせて会話を楽しむデスクトップマスコットです。
- 伺かは、ベースウェア（舞台）・ゴースト（心）・シェル（体）・バルーン（吹き出し）などの部品の組み合わせでできています。
- ゴーストの中では SHIORI がイベントを受け取り、さくらスクリプトでセリフを返します。SAORI や MAKOTO はその働きを補う部品です。
- 多くのゴーストは \0 側（メインキャラクター）と \1 側（サブキャラクター）の二人組で、さくら側・うにゅう側という伝統的な呼び方もあります。
- この本では SSP を使い、ことねとぴーすけの「はじめてのゴースト」を作ります。

## 練習問題

1. 次の部品を、「心」「体」「吹き出し」「舞台」に分けてください：シェル、ベースウェア、ゴースト、バルーン。

<details>
<summary>答え</summary>

- 心：ゴースト
- 体：シェル
- 吹き出し：バルーン
- 舞台：ベースウェア

</details>

2. バルーンとシェルは、どちらも付け替えられる部品です。持ち主の違いを説明してください。

<details>
<summary>答え</summary>

シェルは特定のゴーストの中（`shell` フォルダ）に入っていて、そのゴースト専用です。バルーンはベースウェアに置かれ、すべてのゴーストで共有されます。

</details>

3. ユーザーがゴーストの頭をなでてから、ゴーストが反応のセリフを話すまでの流れを、「イベント」「SHIORI」「さくらスクリプト」という言葉を使って説明してください。

<details>
<summary>ヒント</summary>

なでられたことをベースウェアがイベントとして SHIORI に知らせ、SHIORI がセリフをさくらスクリプトにして返し、ベースウェアが表示します。

</details>
